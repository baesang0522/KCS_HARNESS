# KCS_HARNESS

Excel Add-in에서 모델규격·해외거래처 데이터를 작업 시트로 가져와 전처리하고, 사람이 결과를 검토하는 PoC입니다.

## 사용 흐름

1. 홈에서 업무를 선택합니다. 머리글을 포함한 원본 범위를 가져옵니다.
2. 필수 **서로 다른 3열**을 지정하고 필요한 추가 열과 설명을 선택합니다.
   - 모델규격: 신고품명 / 거래품명 / 모델규격
   - 해외거래처: 국가코드 / 해외거래처부호 / 해외거래처 상호
3. **작업 시작**을 누르면 선택한 열의 계산된 값과 표시 형식을 새 작업 시트에 복사합니다. 원본은 유지합니다.
4. 전처리·문자열 분리·같은 기준의 행에 대표값 적용·문자열 치환·자동 매핑을 설정하고 미리보기를 확인한 후 같은 시트에 결과 열을 만듭니다.
5. 결과 열은 다음 작업의 입력이 됩니다. 직접 고친 값은 다음 연산에서 다시 읽습니다.
6. **현재 대상 열의 최종 결과 확인**으로 행 수·빈 셀 수를 확인하고 결과를 채택합니다. 원본에 덮어쓰지 않습니다.

자연어 요청은 같은 설정 카드를 채우며 자동 실행하지 않습니다. 수식 요청은 현재 대상에서 기존 수식 계획·승인 흐름으로 전환합니다. 선택 대상을 직접 바꾸려면 작업 화면의 범위 변경 또는 수식 화면의 원본 변경을 사용합니다. 작업 시트 위치·열 역할·마지막 결과는 통합문서 설정에 기록되며 **저장된 작업 이어가기**로 불러옵니다.

작업을 마치거나 변경할 값이 없으면 카드는 닫히고 결과 메시지만 남습니다. **작업 화면**으로 다시 열어 후속 작업을 할 수 있으며 진행 전인 카드는 직접 닫을 수도 있습니다. 정제규칙에는 이름만 표시하고 데이터 예시는 표시하지 않습니다. 미리보기에서는 변경 행 수와 결과 열 위치를 확인합니다. 자연어 요청에도 현재 대상의 앞 10행을 전달하며 긴 값은 1,000자까지와 잘림 여부를 함께 전달합니다.

## 처리 기준

- 전처리: 전각 ASCII/공백 변환, 앞뒤 공백 제거, 연속 공백 정리, 대·소문자 통일, 단어·기호 제거. 화면에 표시된 순서대로 실행합니다.
- 단어 제거는 대소문자를 구분하고 온전한 단어·구절을 제거합니다. 기호는 포함된 위치에서 제거합니다. 공백 정리가 필요하면 뒤에 공백 규칙을 둡니다.
- 공백 분리는 연속 공백을 합치고, 직접 지정한 구분자는 그대로 사용합니다. 모든 단어 분리 또는 마지막 단어만 추출을 선택할 수 있습니다. 마지막 단어는 두 단어 이상일 때만 추출하며 그 외에는 빈칸입니다.
- 문자열 치환은 대소문자를 구분해 찾을 문자열을 모두 바꿉니다. 정규식 없이 문자 그대로 찾으며 바꿀 문자열을 비우면 삭제합니다.
- 자동 매핑은 현재 데이터의 값 목록에서 그룹과 대표값을 지정합니다. 앞뒤 공백을 없애고 연속 공백을 하나로 합친 뒤 대문자로 비교하여 같은 그룹의 모든 행을 대표값으로 바꿉니다. 내부 공백을 전부 없애거나 비슷한 값을 추측해 묶지는 않습니다. 지정하지 않은 값과 빈 값은 유지하며 원본 값 기준으로 동시에 적용합니다.
- 같은 기준의 행에 대표값 적용: 판단 기준 열(복수 가능), 값을 바꿀 열, 대표값을 적어 둔 Excel 행 번호를 지정합니다. 공백·대소문자 정리 후 기준값이 같은 모든 행에 해당 행의 현재 셀 값 또는 직접 입력한 대표값을 적용합니다. 다른 행의 값은 유지하며 새 결과 열에 기록합니다. 빈 기준값은 허용하지 않습니다. 기존의 묶음 번호·건수 출력은 제거했습니다.
- 숨겨진 행도 포함합니다. 표시된 대상 범위 밖의 결과 셀은 빈칸입니다.
- 원본 행 ID와 표·열 ID로 대상을 확인합니다. 미리보기 후 값·행 순서·표 구성이 바뀌면 다시 확인합니다. 부분 출력은 자동 재시도하지 않습니다.

## 구조

- `api/router.py`: 라우터 등록을 한곳에서 관리합니다.
- `api/operations.py`, `services/operations/`: 준비된 문자열 연산과 입력 검증. LLM 없이 실행합니다.
- `api/jobs.py`, `services/formula/`: 현재 사용 중인 수식 생성·승인·완료 처리. `/jobs` API 주소는 유지합니다.
- `repositories/conversation_repository.py`: 대화와 작업 문맥을 API 메모리에 보관합니다.
- `agents/request_router.py`, `services/chat.py`: 자연어 분류와 현재 작업 문맥 전달.
- `runtime.py`: 모델 연결과 직접 호출. 일반 대화·후속 설명은 분류와 답변을 한 번에 생성합니다. 수식 계획은 필요한 Excel 표본을 받은 뒤 별도로 생성합니다.
- `static/excel/workspace*`: 공통 필수·추가 열 선택, 작업 시트, 현재 대상 관리.
- `static/excel/operations*`: 연산 설정, 미리보기, 결과 입출력.
- `static/excel/formula*`: 수식 화면과 Excel 반영.

옛 모델규격 전체 LLM 분석·별도 시트 출력 경로, 미사용 해외거래처 유사도 코드, 파일 조사/코드 편집 도구와 PostgreSQL 연결 코드는 제거했습니다. 자동 정제 추천, 유사도 UI, 임의 Python 실행, 과거 작업 재실행·되돌리기는 이번 범위에 포함하지 않습니다.

## 실행과 제한

`src/config.yml`의 환경별 `llm` 설정과 `KCS_ENV`를 사용합니다. 사용하지 않는 `storage`, `workspace`, `agent`, `mcp` 설정은 제거했습니다. API 시작 예: `PYTHONPATH=src KCS_ENV=external uv run uvicorn main:app --workers 1`.

- 작업 시트: 데이터 최대 400,000행, 원본 선택 최대 200열, 최초 복사 최대 100열, 결과 포함 최대 200열.
- 전처리·분리·치환·매핑: 요청당 최대 10,000행. 분리 최대 100열, 미리보기 결과 최대 200만 셀. Excel 읽기·쓰기 묶음은 기존 1,000행을 유지합니다.
- 매핑 목록: 한 번에 최대 1,000개 그룹을 지정합니다. 실제 값 목록은 최대 400,000행·1,600만 자에서 집계하며 화면에서는 검색 결과 최대 100개 그룹을 표시합니다.
- 기준별 대표값 적용: 판단 기준 최대 19열과 바꿀 열 1개, 기준 행을 포함한 전체 범위를 한 번에 처리합니다. 요청의 문자열 총길이는 최대 1,600만 자입니다.
- 수식: 최대 10,000행·20열. 실제 계산은 승인 후 수행합니다. 빈 출력 범위를 다시 확인하며 부분 실패 결과는 사용자가 확인합니다.
- 대화·수식 작업은 API 프로세스 메모리에만 보관하며 서버 재시작 시 사라집니다. 통합문서의 값과 작업 정보는 유지됩니다.
- PoC 서버는 **단일 프로세스(`--workers 1`)**로 실행합니다. 여러 프로세스·서버 사이에는 메모리 상태가 공유되지 않습니다. DB 설치나 접속 설정은 필요하지 않습니다.
- 실제 처리 속도는 Excel 환경과 셀 크기에 따라 달라집니다. OfficeApi 1.9 지원 환경에서 실제 통합문서 확인이 필요합니다.

기존 `tests/`는 이전 기능 기준으로 보존합니다. API 소스에는 독립 실행용 데모나 자체 검증 코드를 두지 않습니다.

화면 HTML은 저장하지 않도록 전달하고, 연결된 JS/CSS에는 파일 내용에 따른 버전을 붙입니다. 기존 화면이 계속 보이면 `src/manifest.xml`을 Excel에 다시 등록해 새 진입 주소 `taskpane-current.html`을 사용하세요. 등록 파일 버전은 1.0.1.0입니다. 실행 환경 확인에서 로드된 화면 버전을 확인할 수 있습니다. API 재시작만으로 이미 열린 화면은 갱신되지 않습니다.

작업 결과 열을 삭제하면 다음 요청이나 작업 화면을 열 때 열 목록·작업 대상·마지막 결과를 함께 갱신합니다. 삭제된 대상은 남아 있는 결과 열 또는 업무 기본 열로 돌아가며, 필수 세 열 삭제는 계속 차단합니다. 입력 검증으로 거절된 채팅 요청은 오래된 요청 문맥을 버리고 다시 보낼 수 있습니다.
