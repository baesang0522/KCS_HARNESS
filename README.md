# KCS_HARNESS

Excel Add-in에서 모델규격·해외거래처 데이터를 작업 시트로 가져와 전처리하고, 사람이 결과를 검토하는 PoC입니다.

## 사용 흐름

1. 홈에서 업무를 선택합니다. 머리글을 포함한 원본 범위를 가져옵니다.
2. 필수 **서로 다른 3열**을 지정하고 필요한 추가 열과 설명을 선택합니다.
   - 모델규격: 신고품명 / 거래품명 / 모델규격
   - 해외거래처: 국가코드 / 해외거래처부호 / 해외거래처 상호
3. **작업 시작**을 누르면 선택한 열의 계산된 값과 표시 형식을 새 작업 시트에 복사합니다. 원본은 유지합니다.
4. 전처리·문자열 분리·같은 기준의 행에 대표값 적용·문자열 치환·자동 매핑을 설정하고 미리보기를 확인한 후 같은 시트에 결과 열을 만듭니다.
5. 결과 열은 다음 작업의 입력이 됩니다. 직접 고친 값은 다음 연산에서 다시 읽습니다.
6. **현재 대상 열의 최종 결과 확인**으로 행 수·빈 셀 수를 확인하고 결과를 채택합니다. 원본에 덮어쓰지 않습니다.

자연어 요청은 같은 설정 카드를 채우며 자동 실행하지 않습니다. 작업표에서 수식을 요청하면 서버가 지정한 실제 입력 열로 수식 계획·승인 흐름을 엽니다. 입력 열이 모호하면 다시 확인하며 마지막 결과 열로 임의 대체하지 않습니다. 수식 화면의 원본 변경으로 직접 범위를 다시 선택할 수도 있습니다. 작업 시트 위치·열 역할·마지막 결과는 통합문서 설정에 기록되며 **저장된 작업 이어가기**로 불러옵니다.

작업을 마치거나 변경할 값이 없으면 카드는 닫히고 결과 메시지만 남습니다. **작업 화면**으로 다시 열어 후속 작업을 할 수 있으며 진행 전인 카드는 직접 닫을 수도 있습니다. 정제규칙에는 이름만 표시하고 데이터 예시는 표시하지 않습니다. 미리보기에서는 변경 행 수와 결과 열 위치를 확인합니다. 자연어 요청에도 현재 대상의 앞 10행을 전달하며 긴 값은 1,000자까지와 잘림 여부를 함께 전달합니다.

## 처리 기준

- 전처리: 전각 ASCII/공백 변환, 앞뒤 공백 제거, 연속 공백 정리, 대·소문자 통일, 단어·기호 제거. 화면에 표시된 순서대로 실행합니다.
- 단어 제거는 대소문자를 구분하고 온전한 단어·구절을 제거합니다. 기호는 포함된 위치에서 제거합니다. 공백 정리가 필요하면 뒤에 공백 규칙을 둡니다.
- 공백 분리는 연속 공백을 합치고, 직접 지정한 구분자는 그대로 사용합니다. 모든 단어 분리 또는 마지막 단어만 추출을 선택할 수 있습니다. 마지막 단어는 두 단어 이상일 때만 추출하며 그 외에는 빈칸입니다.
- 문자열 치환은 대소문자를 구분해 찾을 문자열을 모두 바꿉니다. 정규식 없이 문자 그대로 찾으며 바꿀 문자열을 비우면 삭제합니다.
- 자동 매핑은 현재 데이터의 값 목록에서 그룹과 대표값을 지정합니다. 앞뒤 공백을 없애고 연속 공백을 하나로 합친 뒤 대문자로 비교하여 같은 그룹의 모든 행을 대표값으로 바꿉니다. 내부 공백을 전부 없애거나 비슷한 값을 추측해 묶지는 않습니다. 지정하지 않은 값과 빈 값은 유지하며 원본 값 기준으로 동시에 적용합니다.
- 같은 기준의 행에 대표값 적용: 판단 기준 열(복수 가능), 값을 바꿀 열, 대표값을 적어 둔 Excel 행 번호를 지정합니다. 공백·대소문자 정리 후 기준값이 같은 모든 행에 해당 행의 현재 셀 값 또는 직접 입력한 대표값을 적용합니다. 다른 행의 값은 유지하며 새 결과 열에 기록합니다. 빈 기준값은 허용하지 않습니다. 기존의 묶음 번호·건수 출력은 제거했습니다.
- 숨겨진 행도 포함합니다. 표시된 대상 범위 밖의 결과 셀은 빈칸입니다.
- 원본 행 ID와 표·열 ID로 대상을 확인합니다. 미리보기 후 값·행 순서·표 구성이 바뀌면 다시 확인합니다. 부분 출력은 자동 재시도하지 않습니다.

## 구조와 수정 위치

아래 경로는 `src/` 기준입니다. 파일 길이보다 기능과 상태의 소유권을 기준으로 나눕니다.
기존 전역 팩토리와 `defer` 스크립트 방식을 유지하며 별도 프론트 빌드 도구는 필요하지 않습니다.

### 프론트

| 위치 | 담당 기능 |
| --- | --- |
| `static/excel/taskpane.html`, `taskpane.css` | 화면 마크업·전체 배치, 스크립트 로딩 순서 |
| `static/excel/taskpane.js` | Office 준비 상태, 컨트롤러 생성과 연결, 서버 UI 요청 전달 |
| `static/excel/chat/chat.js` | 대화 표시·저장·복원, 요청 ID, 전송·중지, 전체 작업 중 상태 |
| `static/excel/cleaning_help/` | 도움 카드 열기·닫기, 기능 선택, 작업 카드 위치 복원 |
| `static/excel/workspace/` | 작업표 생성·복원, 현재 작업표·대상·마지막 결과 관리 |
| `static/excel/workspace/table_reader.js` | 표·열·행 ID 확인, 공용 Excel 분할 읽기 |
| `static/excel/operations/` | 정제 설정, 미리보기·적용, 값 매핑, 일반 정제 job 통신 |
| `static/excel/operations/extraction_suggestions.js` | 전체 대상의 추출 패턴 검사와 추천 집계 |
| `static/excel/formula/` | 수식 카드, 입력 확인, Excel 수식 적용 |
| `static/excel/formula/workspace_formula.js` | 현재 작업표의 수식 입력·출력 범위 검증과 결과 열 식별 |
| `static/excel/similarity/` | 유사도 설정·검사·결과 시트 작성 |
| `static/excel/recommendation/` | 조언 대상 검증, 전체 표 집계와 상위 조합 데이터 준비 |
| `static/excel/common/` | API 클라이언트, 마크다운 표시 |
| `static/excel/assets/`, `vendor/` | 이미지, 내부망에서 사용하는 외부 라이브러리 |

작업표와 대상 상태는 `workspace/workspace.js`가 관리합니다. 수식·조언 모듈은 호출 시 현재 상태를
받아 사용하며 별도 작업표 상태를 저장하지 않습니다. 수식 결과를 마지막 결과로 등록하는 작업도
서버 완료 확인 뒤 작업표 컨트롤러에서 수행합니다. 채팅 요청·중지 상태는 채팅 컨트롤러가 관리하고
수식 컨트롤러에서도 같은 요청 수명주기 함수를 사용합니다.

스크립트 이동·추가 시 `taskpane.html`과 테스트의 로딩 경로를 함께 갱신합니다.
공용 표 읽기는 정제·조언 모듈보다 먼저, 각 컨트롤러는 마지막 `taskpane.js`보다 먼저 로드합니다.
`api/taskpane.py`가 중첩 폴더의 JS·CSS에도 내용 해시 버전을 붙입니다. 진입 URL과 API 경로는 유지합니다.

### 백엔드

- `api/`: HTTP 입력·응답과 라우트 등록. `operation_jobs.py`는 일반 정제 작업, `formula_jobs.py`는 수식 작업을 담당합니다.
- `agents/`: 자연어 요청 분류와 도구 입력 구성. 프롬프트는 `prompts/`에 유지합니다.
- `services/chat.py`, `chat_state.py`: 대화 처리와 현재 작업 문맥.
- `services/execution_history.py`: 같은 작업공간의 정제·수식 실행 이력을 현재 열 정보와 연결합니다.
- `services/operations/`: LLM 없이 수행하는 문자열 연산, 검증, 작업 상태 관리.
- `services/formula/planner.py`: 수식 모델 호출, 계획 해석, 원본·출력 범위 검증.
- `services/formula/service.py`: 수식 작업 생성·조회, 계획 진행 상태, 승인·완료·불확실 상태 관리.
- `services/recommendation/selection.py`: 대문자 기준 조합 집계·빈도 선정, 비교용 정렬 기준.
- `services/recommendation/model_io.py`: 입력 예산·분할, 모델 호출, 구조화 응답 검증.
- `services/recommendation/analysis.py`: 계획·검토·통합·근거 확인 단계와 최종 의견 작성.
- `services/recommendation/service.py`: 대화 요청과 분석 연결, 작업 문맥 검증, 오류 처리.
- `repositories/`: 대화 저장소. `runtime.py`, `models/`: 모델 연결.

### 향후 PDF 첨부 경계

PDF 첨부는 아직 구현하지 않았습니다. 추가할 때 프론트 `attachments/`와 백엔드
`api/documents.py`, `services/documents/`에서 업로드·텍스트 추출·페이지 출처를 관리하고,
채팅·조언에는 대화에 연결된 참고자료를 전달합니다. PDF 파싱을 채팅 전송이나 정제 실행 함수에
넣지 않습니다. 미사용 문서 처리 코드·저장소·빈 폴더는 미리 만들지 않습니다.

## 실행과 제한

`src/config.yml`의 환경별 `llm` 설정과 `KCS_ENV`를 사용합니다. 사용하지 않는 `storage`, `workspace`, `agent`, `mcp` 설정은 제거했습니다. API 시작 예: `PYTHONPATH=src KCS_ENV=external uv run uvicorn main:app --workers 1`.

- 작업 시트: 데이터 최대 400,000행, 원본 선택 최대 200열, 최초 복사 최대 100열, 결과 포함 최대 200열.
- 전처리·분리·치환·매핑: 요청당 최대 10,000행. 분리 최대 100열, 미리보기 결과 최대 200만 셀. Excel 읽기·쓰기 묶음은 기존 1,000행을 유지합니다.
- 매핑 목록: 한 번에 최대 1,000개 그룹을 지정합니다. 실제 값 목록은 최대 400,000행·1,600만 자에서 집계하며 화면에서는 검색 결과 최대 100개 그룹을 표시합니다.
- 기준별 대표값 적용: 판단 기준 최대 19열과 바꿀 열 1개, 기준 행을 포함한 전체 범위를 한 번에 처리합니다. 요청의 문자열 총길이는 최대 1,600만 자입니다.
- 수식: 입력 열 최대 20개, 행 범위는 Excel 시트 한도 내에서 처리합니다. 작업표 생성 한도와는 별개입니다. 모델에는 앞 20행 표본을 전달하고, 승인 후 Excel에는 1,000행씩 작성합니다. 빈 출력 범위를 다시 확인하며 부분 실패·완료 미확인은 자동 재실행하지 않습니다.
- 모델규격 AI 조언: 전체 작업표에서 신고품명·거래품명·모델규격명을 대문자로 비교·집계한 빈도 상위 100개 조합을 사용합니다. 추가 열은 각 조합의 첫 실제 행 예시입니다. 입력 분할 예산은 바이트 기준이므로 모델의 실제 토큰 한도를 보장하지 않습니다.
- 대화·정제·수식 작업은 API 프로세스 메모리에만 보관하며 서버 재시작 시 사라집니다. 통합문서의 값과 작업 정보는 유지됩니다.
- PoC 서버는 **단일 프로세스(`--workers 1`)**로 실행합니다. 여러 프로세스·서버 사이에는 메모리 상태가 공유되지 않습니다. DB 설치나 접속 설정은 필요하지 않습니다.
- 실제 처리 속도는 Excel 환경과 셀 크기에 따라 달라집니다. OfficeApi 1.9 지원 환경에서 실제 통합문서 확인이 필요합니다.

## 테스트

프로젝트 루트에서 실행합니다. 설치된 프로젝트 Python 환경과 Node.js를 사용하며 외부 모델 호출은 하지 않습니다.

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/backend -p 'test_*.py'
node --test tests/frontend/*.cjs
```

- `tests/backend/`: API·워크플로우·수식 검증·AI 조언 집계, 페이지 자산 경로와 버전 검사.
- `tests/frontend/`: 수식 대량 작성·실패 처리, 작업 전환, AI 조언 집계, 채팅 중지·도움 카드 연결.
- `tests/helpers/`: Excel API와 화면 DOM의 테스트 대역. 실제 Excel 렌더링·계산 엔진을 대신하지 않습니다.

배포 전 실제 Excel에서 작업표 생성 → 대표값 적용 → 치환 → 이전 결과 대상으로 전환 → 수식 적용을
확인합니다. 정제 도움 카드의 세 기능 전환과 요청 중지도 확인합니다. 테스트·신규 모듈이 누락되지 않게
Git의 새 파일 목록을 확인합니다. API 소스에는 테스트용 실행 코드를 넣지 않습니다.

화면 HTML은 저장하지 않도록 전달하고, 연결된 JS/CSS에는 파일 내용에 따른 버전을 붙입니다. 기존 화면이 계속 보이면 `src/manifest.xml`을 Excel에 다시 등록해 새 진입 주소 `taskpane-current.html`을 사용하세요. 등록 파일 버전은 1.0.1.0입니다. 실행 환경 확인에서 로드된 화면 버전을 확인할 수 있습니다. API 재시작만으로 이미 열린 화면은 갱신되지 않습니다.

작업 결과 열을 삭제하면 다음 요청이나 작업 화면을 열 때 열 목록·작업 대상·마지막 결과를 함께 갱신합니다. 삭제된 대상은 남아 있는 결과 열 또는 업무 기본 열로 돌아가며, 필수 세 열 삭제는 계속 차단합니다. 입력 검증으로 거절된 채팅 요청은 오래된 요청 문맥을 버리고 다시 보낼 수 있습니다.
