# KCS_HARNESS

Excel Add-in에서 모델규격·해외거래처 데이터를 작업 시트로 가져와 전처리하고, 사람이 결과를 검토하는 PoC입니다.

## 조사 에이전트 개발 체크리스트

계획 개정: 2026-11-19. 기존 기능을 재사용해 조사 목표를 수행하는 에이전트를 완성한다. 2026-11-18까지의 완료 내역과 검증 기록은 아래에 유지한다. 미완료 체크 항목과 UI 개선 항목은 개발 계획이며 현재 지원 기능을 뜻하지 않는다.

### 합의한 업무 범위

- 사용자가 방법을 지정하면 요청한 단계만 실행하고, 결과를 요청하면 에이전트가 필요한 도구를 이어서 사용한다. 두 흐름은 같은 조사 상태와 실행 도구를 공유한다.
- PDF에 나온 거래처·품목에 대응하는 데이터를 먼저 찾아 결과를 보여준다. 문서 제목이 ‘부과대상에서 제외되는’ 목록이어도 이를 이유로 검색 결과에서 빼거나 최종 판단을 자동으로 내리지 않는다.
- 결과를 본 사용자가 수정하거나 확정한다. 명확한 조회는 불필요한 사전 확인 없이 진행하고, 불명확한 후보·누락 정보는 결과에 표시한다. 기존 값 변경은 기존 미리보기·적용 절차를 유지한다.
- 사용자가 작업된 열을 직접 고치거나 일부 값만 바꾸는 것도 정상 흐름이다. 예를 들어 기존 열의 일부 `Y`를 `N`으로 바꾼 뒤 최신 값으로 작업을 이어간다.
- 기업 → 품목 순서를 강제하지 않는다. 특정 판정 열 이름이나 `Y/N` 값도 강제하지 않는다.
- 원본 데이터는 유지한다. 선별 결과, 사용자 판단, 최종 확정을 구분하고 범위 밖 행을 변경하지 않는다.

### 현재 확인한 기반

- [x] 제공된 PDF 두 개를 기존 추출기로 읽어 본문·표 추출 확인(2026-11-18).
- [x] 기존 작업 열의 일부 값을 덮어쓰는 기능(예: `Y → N`): 사용자가 실제 Excel 수동 테스트로 확인(2026-11-17). 조사 에이전트 전체 흐름의 검증과는 구분한다.

재사용 대상: PDF 첨부·페이지 조회, 원본 보관·작업표 생성·열 추가, 행·열 ID 연결, 전처리·치환·분리·매핑·대표값 적용, 유사도·묶음 검토, 수식 계산·값 저장, AI 의견, 쓰기 전 변경 검증, 개별 실행 기록·중복 실행 방어.

### 현재 화면과 채팅 작업 흐름 — 2026-11-19

화면에는 작업데이터 준비, 추가 열별 입력카드, 원본 열 추가, PDF 첨부, 추출내용 보기만 남긴다. 정제·치환·분리·그룹 통일·유사도·수식·역할·작업 범위 설정은 채팅으로 요청한다. 별도 설정 카드와 정제 도움 화면은 제거했다.

1. “공급자명 연속 공백 정리해줘” → 툴이 처리 규칙을 전달하고 실제 작업표 전체 대상에서 미리보기를 계산한다. 쓰기는 아직 하지 않는다.
2. 채팅에 대상·처리 행 수·변경 행 수·저장 열·전후 예시를 표시한다. 전체 결과는 접어서 페이지별로 볼 수 있다.
3. 정제의 기본 저장 위치는 새 열이다. “공급자명 정제라는 새 열에”, “기존 공급자명 열에”처럼 저장 위치를 지정하거나 대기 중인 미리보기의 위치만 바꿀 수 있다. 위치를 바꾸면 이전 확인 버튼을 무효화하고 다시 계산한다. ‘기존 열’은 작업표의 열이다.
4. 채팅의 **적용/취소** 버튼 또는 “적용해줘”/“취소”로 현재 미리보기만 처리한다. 완료 문구는 Excel 쓰기와 실행 기록이 확인된 뒤 표시한다. 실패·완료 미확인 상태에서 자동 재적용하지 않는다.
5. PDF 검토 시트 수정 후 추출내용 패널의 **수정 내용 반영** 버튼을 누르거나 “PDF 수정 내용 반영”이라고 요청한다. 개별 PDF의 전처리·수정 반영·추출 재시도도 채팅 도구로 연결된다. “새 조사 시작”, “최종 결과 기록”, “쓰기 결과 확인”도 채팅으로 요청한다.

추출내용 패널은 입력창 바로 위에서 열리고, 긴 내용은 패널 안에서 따로 스크롤한다. 대화 영역의 크기와 읽던 위치는 바꾸지 않는다. 닫기 버튼·추출내용 닫기·Esc로 닫을 수 있다. **수정 내용 반영**은 채팅 미리보기를 준비하는 버튼이며, 최종 적용은 기존 적용/취소 확인을 따른다.

수식은 적용 전에 **계산 계획**을 보여준다. 실제 계산 결과인 것처럼 미리 표시하지 않는다. 기존의 빈 범위·입력 범위 중복 금지·불확실한 쓰기 재실행 금지 보호를 유지한다. 수식의 기존 결과 열은 빈 열이어야 하며, 여러 결과 열의 개별 재배치는 지원하지 않는다. 일반 정제의 기존 열 덮어쓰기는 실제 전후 값을 확인한 후 가능하다.

자동 검증은 도구 설정→응답 형식→채팅 미리보기→명시적 적용, 저장 위치 변경, 오래된 버튼, 직접 셀 편집, PDF별 반영, 조건 범위·복구 회귀를 포함한다. 실제 Excel 추가 기능에서의 클릭·레이아웃·대량 데이터 검증은 별도로 필요하다. 아래 기존 완료 기록은 당시 상태를 그대로 보존한다.

### 앞으로 진행할 순서

| 개발 단계 | 범위 | 완료 판단 |
| --- | --- | --- |
| 1 | 기존 기능 안정화·쓰기 결과 복구 | 상태와 의존 관계가 정확하고, 완료 미확인 쓰기를 재실행 없이 확인할 수 있음 |
| 2 | 거래처 선별 최소 흐름·필요한 도구 범위 통일 | PDF에서 실제 후보·행·부호·건수·근거까지 연결 |
| 3 | 거래처 흐름의 실제 Excel·사용성 검증 | 개발자 설명 없이 검토·수정·이어가기 가능 |
| 4 | 품목 조건·나머지 도구 범위 연결 | HS·규격·두께·경계값을 처리하고 도구 전환 시 범위 유지 |
| 5 | 조사 저장·복구 | 서버 재시작·화면 새로고침 후 같은 조사로 안전하게 복귀 |
| 6 | 전체 회귀·성능 검증 | 기능 조합·직접 수정·중지·부분 실패·대량 데이터 검증 |

실제 Excel 검증과 UI 개선은 각 단계에 포함한다. 3단계는 첫 거래처 흐름을 사용자가 끝까지 수행하는 검증이고, 6단계는 품목·저장 복구까지 연결한 뒤의 전체 회귀 검증이다. 개발 순서는 사용자의 기업 → 품목 작업 순서를 강제하지 않는다.

### 기존 완료 내역과 검증 기록 — 2026-11-18 기준

아래 기존 작업 묶음 1~3의 체크·날짜·검증 결과·당시 제약은 이력으로 유지한다. 체크는 해당 시점의 구현과 명시한 검증 범위를 뜻하며 실제 Excel 전체 검증이나 이후 발견된 결함의 해결을 뜻하지 않는다. 아래 기록에 나오는 작업 묶음 번호는 개정 전 번호다. 이후 할 일은 뒤의 ‘개발 단계별 작업과 완료 기준’을 따른다.

- 기존 묶음 4(거래처)는 새 개발 단계 2·3, 기존 묶음 5(품목)는 단계 4로 연결한다.
- 기존 묶음 6(범위 통일)은 단계 2·4에 나눠 연결하고, 기업·모델 AI 의견 주제 연결 오류는 단계 1에서 먼저 다룬다.
- 기존 묶음 7(실제 통합 검증)은 각 단계의 실제 Excel 검증과 단계 3·6으로 분산한다.
- 기존 제목의 작업일은 당시 초기 추정이며 앞으로 남은 기간이나 실제 소요 기간으로 합산하지 않는다.

#### 1. 조사 상태와 PDF 조건 추출·확인 — 4~6일

- [x] 조사 목표, 문서 근거, 구조화된 추출 조건과 연결 작업표를 명시적으로 저장한다. 대화당 작업표 하나를 자동 연결한다.
- [x] PDF에서 거래처·품목·규격·경계값 등 필요한 조건을 추출하고 문서·페이지·근거 문구를 연결한다. 문서 본문은 조사 자료로 취급하고 실행 지시로 따르지 않는다.
- [x] 사용자가 추출 조건을 확인·수정할 수 있게 하고, 이미 명확한 조회 요청을 반복 승인받지 않는다. 불명확한 조건과 문서 누락은 표시한다.

- [x] 참고자료/조사 조건 패널을 ‘추출내용 보기/접기’ 하나로 통합한다.
- [x] 문서와 준비된 작업표를 자동 연결한다. 다른 작업표의 새 조사는 새 대화에서 시작한다.
- [x] 회사 하나당 한 행으로 추출하고 Excel 검토 시트의 수정·추가·삭제를 구조화된 조건에 반영한다. Y/N·상태·내부 ID 열은 만들지 않는다.
- [x] 연속 번호 표의 첫 페이지 헤더·열 위치를 이어받고 빈 열을 보존한다. 모델명 PDF 236개를 실제 첨부·추출·저장하고 원본 셀과 전부 대조했다.

- [x] 새 거래처 검토 표는 `그룹명(한글 회사명) · 회사명(영문) · 근거 페이지` 3열이다. 한글명이 없으면 원문 회사명을 그룹명으로 쓴다. 원문 번호/관계사 그룹은 서버 추출 원본과 통합문서의 원본 근거 기록에 보존한다. 기존 4열 검토 표는 계속 읽을 수 있으며 사용자 수정값을 다시 추출해 덮어쓰지 않는다.

#### 2. 공통 대상 범위와 사용자 판단 관리 — 기존 기능 재사용·남은 연결 작업

기존 구현을 다시 확인해 완료 항목과 연결 작업을 분리했다(2026-11-18). 기존 4~6일 추정은 중복 개발을 포함하므로 남은 작업 기준으로 다시 산정한다.

- [x] 기존 행 ID 기반으로 조건에 맞는 행만 읽고 기존 열을 부분 수정한다. 대상 밖 행과 수동 입력값은 보존한다.
- [x] 직접 수정한 값(`Y → N` 등)은 다음 실행에서 다시 읽는다. 판정 열 이름이나 값을 강제하지 않는다.
- [x] 정렬·열 이동 후에도 행·열 ID로 대상을 확인하고 미리보기 이후 입력·결과값 변경을 감지한다.
- [x] (기존 구현, 현재 보류) 묶음 검토에서 확정·멤버 제외·기존 열 표시와 현재 범위 설정을 제공한다. 현재 범위와 전체 범위를 선택해 읽을 수 있다.
- [x] (기존 구현, 현재 보류) 묶음 검토의 관련 열·멤버가 바뀌면 해당 묶음만 재검토 표시한다. 관계없는 메모 수정·정렬은 확정을 유지한다.
- [x] 조건부 기존 값 변경에서 ‘그중에서’는 현재 작업 행 범위·저장 필터·새 조건을 함께 적용하고, ‘전체에서’는 전체 작업표에 새 조건만 적용한다. 이번 요청이 저장된 기존 필터를 변경하지 않는다.
- [x] 요청 범위를 미리보기에 표시하고, 현재 범위의 판정 열을 수정하는 경우와 10,002행의 마지막 일치 행까지 처리하는 경우를 검증한다.

완료 회신 유실 재현은 추가 기능의 개발자 도구 콘솔에서 아래 코드를 한 번 실행한 뒤 정제 또는 수식을 적용한다. `dropBeforeSend = false`는 서버에 완료가 저장됐으나 응답만 유실된 경우, `true`는 완료 요청이 서버에 도달하지 않은 경우다. 지정한 완료 요청 한 번만 가로채고 원래 연결로 복원한다. 테스트 중단 시에는 추가 기능 화면을 새로 불러와 해제한다.

```javascript
const dropBeforeSend = false;
const originalRequest = window.apiClient.requestJson;
window.apiClient.requestJson = async function (path, options) {
    const body = options && options.body ? JSON.parse(options.body) : null;
    const completion = (/^\/operation-jobs\/.+\/status\?/.test(path) && body && body.status === "APPLIED") ||
        /^\/formula-jobs\/.+\/previews\/.+\/complete$/.test(path);
    if (!completion) return originalRequest(path, options);
    window.apiClient.requestJson = originalRequest;
    if (!dropBeforeSend) await originalRequest(path, options);
    throw new Error("수동테스트: 완료 회신 1회 유실");
};
```

복구의 현재 범위: 쓰기 증거·확인 기록은 기존 실행 기록과 함께 **현재 서버 메모리**에 보관한다. 서버 재시작·장기 저장·통합문서 간 분리는 개발 단계 5다. 값 대조는 범위를 나눠 확인하므로 블록 내부 일부 셀만 일치하거나 행/열 위치가 달라진 경우 판단 불가가 될 수 있다. 사용자 판단은 자동 값 대조와 구분해 기록한다. 출력 범위 자체를 식별할 증거가 없으면 ‘완료 확인’ 메모만으로 성공 처리하지 않고 미확인을 유지한다. 화면을 새로 열어 원래 의존 기록을 복원할 근거가 없으면, 복구한 결과 열은 재검토 대상으로 남긴다.

수동 검증 기록: 아직 없음. 사용한 Excel/모델 환경, 위 번호별 결과, 실패 위치와 재확인 결과를 사용자 테스트 후 추가한다.

#### 개발 단계 2. 거래처 선별 최소 흐름·필요한 도구 범위 통일

구현·자동 검증(2026-11-19, 실제 Excel 확인 대기): `PDF 기준 거래처와 해외거래처상호를 비교해서 그룹명을 붙여줘` 요청은 `match_suppliers`로 연결한다. 확인·반영한 PDF 기준 회사 n개와 현재 작업 범위의 고유 거래처 N개를 n:N으로 비교한다. 기본 자동 매칭은 Levenshtein으로 먼저 비교하고 90점 미만인 거래처만 SequenceMatcher(양방향 평균)로 보완한다. 각 단계의 최고 점수가 **90 이상**이면 한국어 그룹명을 부여하고, 동점은 **저장한 기준 목록에서 뒤에 있는 항목**을 선택한다. PDF 검토 표의 순서를 바꿨다면 수정 내용 반영이 필요하다. 비교 시 대소문자·연속 공백을 통일하며 원본 셀은 유지한다.

고유 거래처를 250개씩 나눠 계산하고 진행 표시·중지를 기존 작업 흐름으로 제공한다. 전체 비교 쌍을 메모리·채팅에 쌓지 않고 거래처별 최고 결과만 보관하므로 이 경로에는 기존 내부 상호 비교의 200자·5만 쌍·5초 제한을 적용하지 않는다. 기존 작업표 읽기·쓰기의 행/셀 한도는 그대로다. 기존 미리보기에서 확인 후 적용하며, 기존 결과가 없으면 새 그룹명·점수 열을 만든다. 90 미만과 빈 거래처의 그룹명은 빈칸이고, 기존 그룹·점수 열이 있으면 재사용해 그룹이 빈 행만 비교한다. 전각 공백도 빈칸으로 처리하며 이미 채워진 그룹과 점수는 읽기 대상에서 제외해 유지한다. 새로 90점 이상 매칭된 행만 기존 그룹명·점수 열에 함께 반영하고, 90점 미만 행은 기존 값 그대로 둔다. 그룹·점수 열을 함께 반영할 때도 미리보기 변경 검증과 쓰기 결과 확인을 유지한다. 비교 후 기준 목록·순서 변경이나 미반영 PDF 수정은 적용 전에 차단한다. 기존 값끼리 비교하는 `inspect_similarity`와 보류한 묶음 검토는 별개이며 자동 기업 동일성 확정을 뜻하지 않는다.

수동 확인: 새 PDF 검토 표가 3열인지 확인 → 수정 내용 반영 → 위 비교 요청 → 그룹명·점수 확인 후 적용. 90점 경계, 동점 시 뒤 항목, 미분류, 동일 거래처 반복 행, 기존 결과 열의 미분류 값 보존을 확인한다. 새 기준·원본 변경 후에는 비교를 다시 요청한다. 이미 분류된 그룹은 재비교하지 않으므로 다시 판단할 행은 사용자가 그룹을 비운 후 요청한다.

자동 모드에서는 한 번의 미리보기·적용으로 두 단계를 처리하며 먼저 90점 이상 나온 결과를 유지한다. 두 방식 모두 미달이면 그룹은 비우고, 새 점수 열에는 마지막 비교 방식의 최고 점수를 표시한다. 기존 결과 열 재사용 시에는 90점 이상 새 매칭만 그룹·점수를 갱신한다. 특정 방식을 명시하면 그 방식만 실행한다.

추가 수동 확인(2026-11-19): 알고리즘을 지정하지 않고 `PDF 기준으로 해외공급자상호를 매칭해서 빈 그룹만 채워줘` 요청 → 자동 매칭 미리보기 → 한 번 적용. 명시적 방식 확인: Levenshtein 적용 → `해외공급자상호를 SequenceMatcher로 비교해서 기존 그룹이 빈 행만 채워줘` 요청 → 미리보기에서 SequenceMatcher 표시·기존 그룹/점수 열 저장 위치 확인 → 적용. 기존 그룹·점수와 90점 미만 행은 그대로이고 새로 매칭된 행만 두 열에 채워지는지 확인한다. 기본 이름의 결과 열은 자동 재사용한다. 이름을 바꾼 결과 열은 요청에서 지정하면 실제 ID를 사용한다. 자동 테스트 통과, 실제 Excel·실제 모델 라우팅 확인은 대기.

- [ ] 문서의 상호·관계사 설명을 데이터의 공급자상호·부호·국가 열에 연결한다. 문서에 없는 부호를 만들어내지 않는다.
- [ ] 정확 대조와 기존 전처리·유사도를 연결해 약칭·공백·철자 변형 후보를 찾고, 실제 행·부호·건수·문서 근거를 보여준다. 보류된 묶음 검토 전체를 다시 활성화하는 것을 선행 조건으로 삼지 않는다.
- [ ] 이 흐름에서 사용하는 조회·정제·유사도에 동일한 현재 행/열 범위를 전달한다. 모든 도구의 범위 통일이 끝날 때까지 거래처 흐름을 미루지 않는다.
- [ ] 사용자가 허용한 테스트 대체 규칙의 적용 조건을 확인하고 적용 사실을 결과에 남긴다. 테스트 예외를 일반 조사 규칙으로 고정하지 않는다.
- [ ] 결과를 본 사용자의 수정·판단을 받아 최신 값으로 이어간다. 사용자 요청 없는 최종 기업 동일성 판단이나 값 변경은 확정하지 않는다.

완료 기준: 실제 Excel 사본에서 ‘PDF에 나온 해외거래처 관련 데이터를 뽑아줘’ 요청으로 후보·대응 행·부호·건수·근거를 확인한다. 회사명이나 판정값을 직접 수정한 뒤 최신 상태로 이어가고, 도구 전환으로 범위가 넓어지거나 대상 밖 행이 바뀌지 않는다.

## 사용 흐름

1. 홈에서 **통합 조사 시작**을 선택하고 머리글을 포함한 원본 범위를 등록합니다. 처음 선택하지 않은 같은 원본 시트의 열도 나중에 추가할 수 있습니다.
2. 지금 가져올 열을 최소 하나 선택합니다. 공급자명·부호·국가·품명·모델규격 역할은 선택 사항이며 나중에 지정할 수 있습니다. 특정 이름의 판정 열을 요구하지 않습니다.
3. **작업 시작**을 누르면 등록 범위 전체의 계산된 값과 표시 형식을 숨김·보호 보관 시트에 복사하고, 선택한 열만 조사 작업표로 가져옵니다. 원본은 수정하지 않습니다. 보관본 때문에 통합문서 용량과 초기 복사 시간이 늘어납니다.
4. 전처리·분리·대표값 적용·치환·매핑·값 지정을 설정합니다. 결과 위치를 **새 열** 또는 **기존 열**로 선택하고 미리보기를 확인한 후 반영합니다. 기존 열은 대상 행의 값만 바뀌며, 다른 행의 기존 값은 유지됩니다. 수식 셀은 덮어쓰지 않습니다.
5. 사람이 작업표 안에 만든 열도 **열 목록 새로고침**으로 사용할 수 있습니다. 열 이름·위치 변경과 표 전체 정렬 후에도 ID로 연결하며, 직접 고친 값은 다음 연산에서 다시 읽습니다. 삭제 후 같은 이름으로 만든 열은 별개입니다.
6. 상단 **작업 범위**에서 조건 열·조건·비교할 값을 고르고 **범위 적용**을 누릅니다. 예: `판정 → 같음 → Y`. 묶음 생성이나 셀 값 변경 없이 다음 작업의 범위를 지정합니다. 새 조건은 기존 조건을 대체하며 **전체 행으로 돌아가기**로 해제합니다. 직접 수정한 셀 값은 다음 작업에서 다시 읽습니다.
7. **열 추가**는 같은 원본 시트의 머리글을 조회합니다. 처음 보관한 열은 당시 값을, 처음 선택하지 않은 열은 현재 원본 값을 읽어 작업표 전체 행에 추가합니다. 작업표의 원본 행 번호로 맞추므로 작업표를 정렬해도 대응하며 숫자·논리값·표시 형식도 유지합니다. 기존 열을 덮어쓰지 않습니다.
8. **현재 대상 열의 최종 결과 확인**으로 행 수·빈 셀 수를 확인하고 결과를 채택합니다. 확정한 열도 다시 수정·확정할 수 있으며 잠금이나 과거 값 복원 기능은 아닙니다.

기존 개별 작업표도 이어서 사용할 수 있지만 자동 병합하지 않습니다. 원본 보관본이 없는 이전 작업표는 원본 열 추가를 지원하지 않습니다. 내부 **원본 행 번호**는 수정·삭제하지 않습니다. 행 ID가 없거나 중복된 행을 발견하면 처리를 중단합니다. 열 이동은 표 열 전체를 이동하고 정렬은 표 전체에 적용합니다. 셀 값만 복사해 다른 열을 덮어쓰는 동작은 열 이동으로 판별하지 않습니다.

상단 버튼은 작업표가 없으면 **작업 준비**, 준비된 작업표가 있으면 **열 추가**로 표시됩니다. **열 추가**를 누르면 원본 열을 체크박스로 여러 개 선택해 한 번에 가져오는 화면이 열리며, 전처리 완료로 작업 카드가 닫혀도 사용할 수 있습니다. 열 추가 화면에는 원본 열 목록과 가져오기 조작만 표시하며 전처리·묶음 검토·열 역할 설정은 표시하지 않습니다. 가져오기 후에도 같은 화면을 유지합니다. 작업 범위는 채팅으로 지정합니다. 저장된 행 조건은 유지하며 채팅 미리보기에 현재 조건을 표시합니다. 여러 열 중 일부만 성공하면 성공한 열의 연결 정보를 먼저 저장하고 나머지는 중단합니다. 원본 시트에 더 가져올 열이 없으면 안내를 표시하고 가져오기 버튼을 비활성화합니다.

처음 선택하지 않은 열을 가져올 때는 **원본 행을 정렬·추가·삭제하지 않았다는 확인**이 필요합니다. 기존 보관값과 현재 원본을 행별로 대조하고, 차이가 있으면 쓰기 전에 중단합니다. 원본 자체에는 고유 행 ID가 없으므로 보관값이 똑같은 중복 행끼리의 재정렬은 검출할 수 없습니다. 원본 순서가 바뀌었다면 이 확인란을 선택하지 않습니다. 이 제한은 원본 시트에 해당하며 작업표의 정렬·정제는 가능합니다. 같은 머리글 행을 사용하는 원본의 사용 열 최대 200개를 조회합니다.

단일 단계 자연어 요청은 같은 설정 카드를 채우고 기존 미리보기·적용 절차를 따릅니다. 목표형 요청은 현재 범위의 읽기·비교를 이어서 실행하고 결과를 보여주며, 셀 쓰기는 사용자 적용을 기다립니다. 작업표에서 수식을 요청하면 서버가 지정한 실제 입력 열로 수식 계획·승인 흐름을 엽니다. 작업표와 입력 열 ID가 확인되면 Excel에서 셀을 따로 선택할 필요 없이 해당 열과 현재 표의 전체 데이터 행을 읽습니다. 이전 작업의 저장된 행 범위는 재사용하지 않습니다. 입력 열이 모호하면 다시 확인하며 마지막 결과 열로 임의 대체하지 않습니다. 수식 화면의 원본 변경으로 직접 범위를 다시 선택할 수도 있습니다. 작업 시트 위치·열 역할·마지막 결과는 통합문서 설정에 기록되며 **저장된 작업 이어가기**로 불러옵니다.

작업을 마치거나 변경할 값이 없으면 카드는 닫히고 결과 메시지만 남습니다. 상단 **열 추가**는 원본 열 가져오기만 열고, **작업 범위**는 다음 작업의 조건을 지정합니다. 후속 처리 요청은 채팅으로 이어갈 수 있으며 진행 전인 카드는 직접 닫을 수도 있습니다. 정제규칙에는 이름만 표시하고 데이터 예시는 표시하지 않습니다. 미리보기에서는 변경 행 수와 결과 열 위치를 확인합니다. 자연어 요청에도 현재 대상의 앞 10행을 전달하며 긴 값은 1,000자까지와 잘림 여부를 함께 전달합니다.

## 작업 범위 추가·제외와 후속 결과 재검토

새 화면 없이 기존 채팅에서 작업 범위만 변경합니다. 예: **현재 대상에 회사명이 B인 행도 추가해줘**, **그중 국가가 중국인 행은 제외해줘**, **판정이 Y인 행만 작업 대상으로 지정해줘**, **전체 행으로 돌아가줘**. 조건 열·비교할 값이 명확해야 하며 기업 동일성이나 비슷한 표기를 자동 판단하지 않습니다.

- 추가는 현재 대상과 조건 일치 행을 합치고, 제외는 현재 대상에서 조건 일치 행을 뺍니다. 요청 순서대로 적용하므로 제외 후 다시 포함한 행은 대상으로 돌아옵니다. 현재 대상이 전체 행이면 추가해도 전체 행입니다.
- 셀 값은 바꾸지 않습니다. 기존 **작업 범위** 화면과 작업 카드에는 결합된 조건을 표시하고 채팅 결과에는 실제 대상 건수를 표시합니다. 작업 범위 화면에서 **범위 적용**을 누르면 기존 조건 전체를 새 단일 조건으로 대체합니다.
- 저장된 조건은 매번 현재 값으로 평가합니다. 범위가 0행이어도 채팅으로 다시 추가하거나 전체 범위로 돌아갈 수 있습니다. 전체 행으로 돌아가면 이전에 일부 행만 선택했어도 작업표 전체로 복귀합니다. 정렬·열 이름 변경은 행·열 ID로 연결하며, 삭제된 조건 열은 자동으로 전체 범위로 바꾸지 않습니다.
- 정제·수식 결과를 작성할 때 사용한 입력 열·실제 대상 행·조건의 비교 기준을 통합문서 작업 정보에 저장합니다. 이후 채팅·미리보기·범위 변경·저장된 작업 복구 시 다시 읽어 비교합니다. 실시간 편집 감시나 자동 재계산은 하지 않습니다.
- 입력이나 조건의 대상 행이 달라지면 화면 상단에 **재검토 필요: 결과 열 이름**을 표시합니다. 그 결과에 의존한 후속 결과도 재검토 상태로 바뀝니다. 무관한 메모 변경·행 정렬·열 이동·이름 변경은 상태를 바꾸지 않습니다. 재검토 결과는 실행 문맥에서도 최신 확정 결과로 취급하지 않습니다.
- 기존 결과값은 보존합니다. 해당 결과를 다시 처리해 같은 대상 행의 결과를 갱신하면 그 결과의 상태를 해제합니다. 다시 계산한 값이 기존 값과 같아도 현재 값을 검증한 뒤 해제합니다. 후속 결과는 각각 다시 처리해야 합니다. 다른 일부 행만 재처리한 경우에는 덮지 않은 기존 결과의 재검토 상태를 보수적으로 유지합니다.
- 의존 관계 추적은 이번 버전에서 새로 실행하거나 다시 처리한 결과부터 시작합니다. 이전 버전에서 만든 결과의 과거 입력값은 추정해서 채우지 않습니다. 통합문서 파일도 저장해야 닫은 뒤 기록이 유지됩니다. 조건 범위 수식의 기존 차단은 개발 단계 4에서 실제 지원·검증하기 전까지 유지합니다.

## 처리 기준

- 전처리: 전각 ASCII/공백 변환, 앞뒤 공백 제거, 연속 공백 정리, 대·소문자 통일, 단어·기호 제거. 화면에 표시된 순서대로 실행합니다.
- 단어 제거는 대소문자를 구분하고 온전한 단어·구절을 제거합니다. 기호는 포함된 위치에서 제거합니다. 공백 정리가 필요하면 뒤에 공백 규칙을 둡니다.
- 공백 분리는 연속 공백을 합치고, 직접 지정한 구분자는 그대로 사용합니다. 모든 단어 분리 또는 마지막 단어만 추출을 선택할 수 있습니다. 마지막 단어는 두 단어 이상일 때만 추출하며 그 외에는 빈칸입니다.
- 문자열 치환은 대소문자를 구분해 찾을 문자열을 모두 바꿉니다. 정규식 없이 문자 그대로 찾으며 바꿀 문자열을 비우면 삭제합니다.
- 자동 매핑은 현재 데이터의 값 목록에서 그룹과 대표값을 지정합니다. 앞뒤 공백을 없애고 연속 공백을 하나로 합친 뒤 대문자로 비교하여 같은 그룹의 모든 행을 대표값으로 바꿉니다. 내부 공백을 전부 없애거나 비슷한 값을 추측해 묶지는 않습니다. 지정하지 않은 값과 빈 값은 유지하며 원본 값 기준으로 동시에 적용합니다.
- 같은 기준의 행에 대표값 적용: 판단 기준 열(복수 가능), 값을 바꿀 열, 대표값을 적어 둔 Excel 행 번호를 지정합니다. 공백·대소문자 정리 후 기준값이 같은 모든 행에 해당 행의 현재 셀 값 또는 직접 입력한 대표값을 적용합니다. 현재 작업 조건에 맞는 행 안에서 처리하며 기준 행도 대상에 포함되어야 합니다. 빈 기준값은 허용하지 않습니다. 기존의 묶음 번호·건수 출력은 제거했습니다.
- 값 지정: 대상 행에 입력한 문자열을 그대로 기록합니다. 빈 문자열로 비울 수도 있습니다.
- 그룹화·모델 추출의 기존 열 반영은 첫 결과값만 기록합니다. 상태는 미리보기에서 확인하고, 새 열을 선택하면 상태 열도 만듭니다. 여러 열 분리 결과는 새 열로만 저장합니다.
- Excel 화면에서 숨긴 행도 포함합니다. 애드인에 저장한 작업 조건으로 처리 대상을 제한하며, 새 결과 열의 대상 밖은 빈칸이고 기존 결과 열의 대상 밖은 유지합니다.
- 조건이 설정된 작업표의 수식 채우기는 현재 차단합니다. 조건을 해제하고 전체 범위를 명시적으로 선택한 경우에만 기존 수식 기능을 사용합니다.
- 원본 행 ID와 표·열 ID로 대상을 확인합니다. 미리보기 후 값·행 순서·표 구성이 바뀌면 다시 확인합니다. 부분 출력은 자동 재시도하지 않습니다.

## 구조와 수정 위치

아래 경로는 `src/` 기준입니다. 파일 길이보다 기능과 상태의 소유권을 기준으로 나눕니다.
기존 전역 팩토리와 `defer` 스크립트 방식을 유지하며 별도 프론트 빌드 도구는 필요하지 않습니다.

작업표와 대상 상태는 `workspace/workspace.js`가 관리합니다. 수식·조언 모듈은 호출 시 현재 상태를
받아 사용하며 별도 작업표 상태를 저장하지 않습니다. 수식 결과를 마지막 결과로 등록하는 작업도
서버 완료 확인 뒤 작업표 컨트롤러에서 수행합니다. 채팅 요청·중지 상태는 채팅 컨트롤러가 관리하고
수식 컨트롤러에서도 같은 요청 수명주기 함수를 사용합니다.

스크립트 이동·추가 시 `taskpane.html`과 테스트의 로딩 경로를 함께 갱신합니다.
공용 표 읽기는 정제·조언 모듈보다 먼저, 각 컨트롤러는 마지막 `taskpane.js`보다 먼저 로드합니다.
`api/taskpane.py`가 중첩 폴더의 JS·CSS에도 내용 해시 버전을 붙입니다. 진입 URL과 API 경로는 유지합니다.

### 백엔드

- `api/`: HTTP 입력·응답과 라우트 등록. `operation_jobs.py`는 일반 정제 작업, `formula_jobs.py`는 수식 작업을 담당합니다.
- `agents/`: 자연어 요청 분류와 도구 입력 구성. 프롬프트는 `prompts/`에 유지합니다.
- `services/chat.py`, `chat_state.py`: 대화 처리와 현재 작업 문맥.
- `services/execution_history.py`: 같은 작업공간의 정제·수식 실행 이력을 현재 열 정보와 연결합니다.
- `services/operations/`: LLM 없이 수행하는 문자열 연산, 검증, 작업 상태 관리.
- `services/formula/planner.py`: 수식 모델 호출, 계획 해석, 원본·출력 범위 검증.
- `services/formula/service.py`: 수식 작업 생성·조회, 계획 진행 상태, 승인·완료·불확실 상태 관리.
- `services/recommendation/selection.py`: 대문자 기준 조합 집계·빈도 선정.
- `services/recommendation/model_io.py`: 입력 예산·분할, 모델 호출, 구조화 응답 검증.
- `services/recommendation/analysis.py`: 상위 조합 일괄 분석·제안 전체 일괄 검증과 최종 의견 작성. 해외거래처는 전체 행을 분할 검토·통합.
- `services/recommendation/service.py`: 대화 요청과 분석 연결, 작업 문맥 검증, 오류 처리.
- `repositories/`: 대화 저장소. `runtime.py`, `models/`: 모델 연결.

### 오류 문구의 책임

- 업무·설정 오류는 서버에서 결정하고 `detail` 문자열로 응답합니다. `api/errors.py`가 입력 검증 오류를 정리하며, 프론트는 서버 문구에 일반적인 실패 문구를 덧붙이지 않습니다.
- 정제 옵션의 실행 가능 여부는 `Operation.validate_ready()`에서 검사합니다. 작업 생성 때 먼저 검사하므로 잘못된 설정으로 Excel 전체 데이터를 읽지 않습니다. 자연어 라우터용 미완성 설정은 계속 허용합니다.
- Excel에서 다시 확인해야 하는 작업표·모델규격명 열 오류의 공통 문구는 `services/error_messages.json`에만 둡니다. 서버가 HTML에 안전한 JSON으로 포함하고 `common/error_messages.js`가 읽습니다. 같은 문구를 프론트 소스에 복사하지 않습니다.
- Excel 연결·범위 변경·쓰기 실패 등 클라이언트만 판단할 수 있는 검사는 유지합니다. 일부 작성·완료 미확인 경고는 재실행에 따른 중복 쓰기를 막기 위해 유지합니다.
- 서버 응답을 받을 수 없는 연결 실패·프록시 오류·잘못된 응답은 `common/api_client.js`에서 안내합니다. 요청 중지의 `AbortError`는 변환하지 않습니다.

### PDF 첨부와 추출내용 검토

1. 입력창의 **PDF 첨부**로 선택하거나 입력창 안으로 PDF를 드래그 드롭합니다. 여러 PDF를 선택할 수 있으며 순서대로 처리합니다.
2. 본문·표를 읽고 회사·품목과 근거를 구조화한 뒤 **새 Excel 검토 시트**를 자동으로 엽니다. 순번과 강종·규격 헤더가 있는 모델 목록은 셀에서 직접 추출합니다. 그 외 문서는 기존 AI 의견 모델에 원본 파일 대신 추출한 본문을 전달합니다.
3. 검토 시트는 Excel 시트 탭에서 확인합니다. **추출내용 보기 / 접기**에는 문서별 **전처리**, **수정 내용 반영**만 둡니다. 추출 또는 시트 생성 실패 시 **추출 다시 시도**로 재시도합니다.
4. 검토 시트의 **표 안에서** 셀 수정·행 추가·행 삭제 후 **수정 내용 반영**을 누릅니다. 행 전체를 비워도 삭제로 처리합니다. 정렬·필터로 숨겨진 행도 읽으며, 삭제하려면 행을 삭제해야 합니다.
5. 반영된 조건은 최근 대화 10턴과 별도로 채팅 문맥에 전달됩니다. 시트에 미반영 수정이 있으면 대화 요청 전에 반영을 안내합니다. 실제 거래 행 추출·최종 포함/제외 판단은 아직 실행하지 않습니다.

검토 표에는 필요한 열만 둡니다. 내부 ID나 판정 Y/N 열을 추가하지 않습니다.

| 종류 | 표시 열 |
| --- | --- |
| 거래처 | 그룹, 구분, 회사명, 근거 페이지 |
| 품목 | 그룹, HS, 규격, 조건, 근거 페이지 |
| 기타 조건 | 그룹, 내용, 근거 페이지 |

- 거래처의 **구분에는 한글 회사명**, **회사명에는 영문 회사명**을 둡니다. 예: `바오 스틸` / `Baoshan Iron & Steel Co., Ltd.`. 한글명이 없으면 구분은 비워도 됩니다. 영문명이 없으면 원문 이름을 회사명에 남기며 번역명을 만들지 않습니다.
- 같은 제조사와 관계 수출사는 같은 그룹을 사용하고 관계 설명은 추출 설명·원문 근거에 보존합니다. ‘관계 수출사’를 임의로 ‘자회사’로 바꾸지 않습니다.
- 연속 번호 표는 첫 페이지의 헤더와 열 위치를 다음 페이지에 이어 적용합니다. 빈 열을 당겨 붙이지 않으며, 강종 목록의 비어 있지 않은 셀 하나를 검토 행 하나로 만듭니다. 영문 괄호 속 별칭은 규격에 남기고 한글 주석은 조건에 보존합니다.
- 품목 한 행의 HS는 쉼표로 구분한 OR 목록이고 규격·조건과는 AND입니다. 다른 대안은 별도 행으로 둡니다. 두께의 단위·이상/초과를 조건에 남깁니다.
- 근거 페이지는 `1` 또는 `1, 2`처럼 입력합니다. 사용자가 추가한 항목은 비워도 됩니다. 존재하지 않거나 읽을 수 없는 페이지는 반영하지 않습니다.
- 열 이름과 순서는 유지합니다. 잘못된 필수값·수식·오래된 검토본의 반영은 거절하고 사용자 시트를 보존합니다.
- 모델은 서버가 부여한 페이지·구절 번호를 선택하고, 인용문은 서버가 원문에서 그대로 가져옵니다. 표의 `<br>`나 줄바꿈을 AI가 다시 쓰는 과정의 불일치를 방지합니다. 원래 모델의 추출값과 인용 근거는 서버에 별도로 보존합니다. 수정한 항목을 원문 인용과 일치한다고 주장하지 않으며 사용자 수정값과 참고 페이지로 구분합니다.
- ‘제외되는 공급자/품목’이라는 제목만 보고 대상을 자동으로 제거하지 않습니다. 문서에 나온 대상을 먼저 나열합니다.
- **한 대화에 활성 작업표 하나**, 문서는 여러 개입니다. 먼저 첨부한 PDF도 작업표를 준비·복구하면 자동 연결합니다. 다른 시트를 클릭해도 조사 대상은 바뀌지 않으며 다른 작업표의 새 조사는 새 대화에서 시작합니다.
- 이미 추출한 PDF의 검토 시트를 다시 열어도 사용자 수정·삭제를 덮어쓰지 않습니다. 서버 반영 후 응답이나 시트 기록 저장에 실패한 경우 같은 버튼으로 반영을 재시도할 수 있습니다.
- PDF만 지우고 검토 시트를 남기는 삭제 버튼은 제공하지 않습니다. 같은 이름으로 재첨부해도 이전 근거를 새 파일로 바꾸지 않습니다.
- PDF 추출 후보 50개, 조사 조건·검토 시트 100개, 조사 상태 64KB 제한을 제거했습니다. 추출·시트 읽기·전처리·수정 반영에서 이 개수로 자르거나 거절하지 않습니다. 일반 문서도 전체 입력이 48KB를 넘는다는 이유로 거절하거나 파일을 나눠 올리도록 요구하지 않습니다. 공통 AI 호출의 요청당 예산을 분할 크기로 사용해 원문 구절을 순서대로 전부 처리합니다. 한 페이지가 길어도 내부에서 나누며, 첫 부분의 공통 전제·진행 중인 그룹·표 헤더는 AI가 선택한 원문 근거와 직전 구절을 다음 요청에 전달합니다. 문서 전체의 분할 횟수·추출 행 수 제한은 추가하지 않았습니다. 셀을 직접 읽는 모델 목록 경로는 그대로 유지합니다.
- 분할 결과는 원래 페이지·구절 번호로 검증합니다. 다음 부분에 아직 보내지 않은 근거를 인용하면 반영하지 않으며, 참고 문맥만 다시 추출한 행은 중복으로 추가하지 않습니다. 중간 실패·중지 시 전체 추출을 저장하지 않고 첨부 문서와 기존 조사 상태를 보존합니다. 다시 시도하면 해당 문서를 처음부터 처리합니다.
- 서버의 대화·문서·조사 상태는 재시작 시 사라집니다. Excel 검토 시트와 통합문서의 반영 기준 기록은 남지만 새 대화에 자동 복원하지 않습니다.

PDF 검토 시트의 공통 전처리:

- 문서의 **전처리**에서 처리할 열과 규칙을 선택합니다. 거래 데이터 작업표의 전처리와 같은 규칙·순서·실행 로직을 사용합니다. 검토 표에는 분리·매핑·유사도·수식 등 다른 도구를 연결하지 않습니다.
- **한글 제거**(`remove_hangul`)와 **괄호 기호만 제거**(`remove_brackets`)는 독립된 옵션입니다. 하나만 선택하거나 둘을 선택해 순서대로 적용할 수 있습니다. 한글 제거는 한글 음절·자모를 제거하고, 괄호 제거는 소·중·대괄호·꺾쇠·전각 괄호 등의 기호만 제거합니다. 괄호 안 내용은 유지합니다.
- 공백 정리·대소문자 변환은 자동으로 추가하지 않습니다. 예를 들어 `회사(ACME)`는 한글 제거만 하면 `(ACME)`, 괄호 제거만 하면 `회사ACME`가 됩니다.
- **변경 내용 확인 → 검토 시트에 적용**으로 선택한 기존 열의 전체 행을 바꿉니다. 필터로 숨긴 행도 포함하며, 새 열을 만들거나 거래 데이터 작업표를 바꾸지 않습니다. 미리보기 이후 표 내용·행 순서·위치가 바뀌면 다시 확인해야 합니다.
- 전처리는 아직 조사 조건 저장이 아닙니다. 시트에서 추가 전처리나 직접 수정을 마친 뒤 기존 **수정 내용 반영**으로 최종 값을 저장합니다. 한글만 있던 필수 셀이 빈칸이 되면 직접 채우거나 해당 행을 삭제한 뒤 반영합니다.

수동 확인 순서:

1. 서버 재시작 후 Excel 추가 기능을 새로 불러옵니다. 해외거래처 PDF는 드롭, 품목 PDF는 첨부 버튼으로 올립니다.
2. 자동 생성된 거래처 표가 네 열인지 확인합니다. 그룹·구분의 한글명·회사명의 영문명이 맞는지 확인합니다. 품목 표의 HS·규격·두께 조건과 누락 안내도 확인합니다.
3. 회사명 하나 수정, 행 하나 추가·삭제, 표 정렬을 해 봅니다. Excel 시트 탭에서 다른 시트로 갔다 돌아와도 수정이 유지되어야 합니다.
4. 반영 전 채팅을 보내면 안내가 나와야 합니다. **수정 내용 반영** 후 ‘이번 조사 조건을 설명해줘’라고 물으면 수정값으로 설명해야 합니다.
5. PDF를 먼저 첨부한 경우 작업표를 준비해 자동 연결을 확인합니다. 다른 시트를 클릭해도 연결이 바뀌지 않아야 합니다. 새 조사·다른 작업표 복구는 새 대화에서 진행합니다.
6. 전처리에서 한글 제거와 괄호 기호 제거를 각각 실행하고, 공백 정리도 별도로 확인합니다. 적용 직후에는 시트만 바뀌고 **수정 내용 반영** 후에 저장된 조건이 바뀌어야 합니다.
7. 모델명 PDF에서 일반재 65개·TMCP 강종 53개·열처리 강종 118개, 합계 236행을 확인합니다. 236번째 행을 수정하고 전처리한 뒤 수정 내용 반영까지 확인합니다.
8. 모든 검토 행 삭제 후 반영, 잘못된 근거 페이지, 추출 중 중지를 확인합니다. 원본 거래 데이터는 바뀌지 않아야 합니다.

자동 검증: 백엔드 115개 + 프론트엔드 134개, 총 249개 통과(2026-11-18). 반복 헤더가 없고 빈 열 경계가 합쳐진 표, 236행·64KB 초과 상태의 저장·수정, 검토 시트 236행 전처리·반영, 한영 회사명 분리를 포함합니다. 추가로 48KB 초과 문서·긴 한 줄·1,500개의 짧은 페이지의 원문 전체 전송, 공통 근거 전달, 중복 방지, 잘못된 근거 거절, 분할 중 실패·중지의 원자적 저장을 검증했습니다. 자동 테스트의 모델 응답·Excel API는 테스트 대역입니다.

실제 파일 검증: 서버 API에 모델명 PDF를 첨부해 추출·저장했고, 236개를 원본 PDF 셀 좌표에서 별도로 읽은 값과 페이지·순번·강종·내용별로 대조해 누락·중복 없이 일치함을 확인했습니다(일반재 65개·TMCP 강종 53개·열처리 강종 118개, 추출 약 0.3초). 같은 대화에서 해외거래처 16개와 품목 4개도 실제 외부 설정 모델로 추출·저장해 총 256개를 확인했습니다. 거래처는 한글·영문 분리 결과를 확인했습니다. 실제 Excel 화면의 드롭 수신·시트 작성은 별도 수동 검증 대상입니다.

자동 분할 실제 모델 검증: 생성한 18쪽 PDF의 추출 본문 73,032바이트를 3회에 나눠 전달했습니다. 84개 원문 구절이 순서대로 빠짐없이 전달됐고, 앞·중간·뒤의 규격 3개에 첫 페이지의 HS 7208511000·두께 10mm 이상 조건이 모두 적용돼 추출·저장됐습니다. 모델명 PDF도 수정 후 236개 원본 대조를 다시 통과했습니다. 기존 업로드 25MB·추출 본문 8MB 등 파일 자원 한도는 이번 AI 분할 변경과 별개로 유지됩니다.

- 서버: `api/documents.py`, `services/documents/`. 화면: `static/excel/documents/`.
- `pymupdf4llm==2.1`과 잠금 파일의 의존성을 설치합니다(`uv sync --locked`).
  내부망에는 서버 OS·Python에 맞는 PyMuPDF·ONNX Runtime 등의 배포 파일도 함께 반입해야 합니다.
  AGPL/상용 라이선스의 배포 조건은 조직에서 확인해야 합니다.
- PDF 본문 읽기는 로컬 프로세스에서 수행하고 OCR은 사용하지 않습니다. 일반 문서의 조건 구조화는 설정된 모델에 본문을 전달하고, 식별 가능한 강종·규격 목록은 표 셀에서 직접 구조화합니다.
  텍스트 없는 페이지는 번호를 표시하고, 전 페이지에 텍스트가 없으면 사용 가능 상태로 등록하지 않습니다.
- 페이지 수 제한은 없습니다. 자원 보호 한도는 파일당 25MB, 추출 본문 8MB,
  대화당 10개·본문 합계 16MB, 파일당 추출 3분, 동시 추출 2개입니다.
- 업로드·읽기 중 기존 전송 버튼이 **중지**로 바뀝니다. 중지 시 서버 요청과 추출 프로세스를 종료합니다.
  원본은 임시 파일로만 사용하고 성공·실패·중지 시 제거합니다. 추출 본문과 연결은 대화 메모리에 보관합니다.
- shortcut: PDF는 현재 API 프로세스의 대화 수명 동안만 보관합니다. 서버 재시작 후 복구가 필요하면 영속 저장을 추가합니다.
  Excel 파일에는 PDF 본문을 저장하지 않습니다. 검토 시트와 그 시트의 대화·문서 식별자 및 마지막 반영값은 통합문서에 저장합니다. 기존 서버 대화가 살아 있으면 첨부 목록과 조건을 다시 조회합니다.

## 실행과 제한

외부용 서버는 프로젝트 루트에서 `./start-external.sh`를 실행합니다.
실행 파일은 프로젝트 폴더로 이동한 뒤 필요한 패키지를 잠금 파일 기준으로 준비하고,
`KCS_ENV=external`로 `http://localhost:8000` 서버를 시작합니다. 종료는 `Ctrl+C`입니다.
`uv`와 `codex`가 필요하며, 모델 호출 전에 `codex login`을 완료해야 합니다.
화면 주소는 `http://localhost:8000/static/excel/taskpane-current.html`입니다.
이 실행 파일은 로컬 외부 모델 테스트용이며 인터넷 공개 서버를 만들지는 않습니다.

`src/config.yml`의 환경별 `llm` 설정과 `KCS_ENV`를 사용합니다. 사용하지 않는 `storage`, `workspace`, `agent`, `mcp` 설정은 제거했습니다. API 시작 예: `PYTHONPATH=src KCS_ENV=external uv run uvicorn main:app --workers 1`.

- 작업 시트: 데이터 최대 400,000행, 원본 선택 최대 200열, 최초 복사 최대 100열, 결과 포함 최대 200열.
- 전처리·분리·치환·매핑: 요청당 최대 10,000행. 분리 최대 100열, 미리보기 결과 최대 200만 셀. Excel 읽기·쓰기 묶음은 기존 1,000행을 유지합니다.
- 매핑 목록: 한 번에 최대 1,000개 그룹을 지정합니다. 실제 값 목록은 최대 400,000행·1,600만 자에서 집계하며 화면에서는 검색 결과 최대 100개 그룹을 표시합니다.
- 기준별 대표값 적용: 판단 기준 최대 19열과 바꿀 열 1개, 기준 행을 포함한 전체 범위를 한 번에 처리합니다. 요청의 문자열 총길이는 최대 1,600만 자입니다.
- 수식: 입력 열 최대 20개, 행 범위는 Excel 시트 한도 내에서 처리합니다. 작업표 생성 한도와는 별개입니다. 모델에는 앞 20행 표본을 전달하고, 승인 후 Excel에는 1,000행씩 작성합니다. 빈 출력 범위를 다시 확인하며 부분 실패·완료 미확인은 자동 재실행하지 않습니다.
- 모델규격 AI 조언: 작업표의 현재 조건에 맞는 행에서 신고품명·거래품명·모델규격명을 대문자로 비교·집계한 빈도 상위 100개 조합을 사용합니다. 추가 열은 각 조합의 첫 실제 행 예시입니다. 상위 조합을 한 번에 분석하고 제안 전체와 중복을 제거한 근거 행을 한 번에 검증합니다. 계획·재정렬 반복은 하지 않습니다. 제안이 없으면 검증 호출은 생략합니다. 입력이 48KB 예산을 넘으면 생략·분할 없이 오류를 안내합니다. 예산은 바이트 기준이므로 모델의 실제 토큰 한도를 보장하지 않습니다. 응답 형식 오류 시 해당 호출을 한 번 재시도할 수 있습니다.
- AI 의견 진행 상황은 기존 입력창 안내 문구에 데이터 읽기 → 분석 → 전체 제안 검증 순서로 표시합니다. 기업 의견은 조건에 맞는 행의 분할 분석과 결과 통합 단계를 표시합니다. 진행 조회는 분석 중에만 수행하며 완료·실패·중지 시 종료합니다.
- 대화·정제·수식 작업은 API 프로세스 메모리에만 보관하며 서버 재시작 시 사라집니다. 통합문서의 값과 작업 정보는 유지됩니다.
- PoC 서버는 **단일 프로세스(`--workers 1`)**로 실행합니다. 여러 프로세스·서버 사이에는 메모리 상태가 공유되지 않습니다. DB 설치나 접속 설정은 필요하지 않습니다.
- 실제 처리 속도는 Excel 환경과 셀 크기에 따라 달라집니다. OfficeApi 1.9 지원 환경에서 실제 통합문서 확인이 필요합니다.

## 내부 모델과 Codex의 공통 하네스

요청 분류는 모델 종류와 관계없이 다음 경로를 사용합니다.

`단일 요청: 채팅 → request_tools.yml → 요청 그래프 → 도구 인자 검증 → 작업 카드 → 사용자 확인 → 기존 실행 처리`

`목표 요청: 채팅 → 조사 실행 → execution.yml → 다음 도구 → Excel 읽기/기존 실행 → 실제 결과 회신 → 다음 행동 또는 사용자 대기/종료`

- Codex도 같은 도구 목록·실제 열 ID·최근 실행 기록을 받습니다. CLI의 구조화된 응답을 도구 호출로 변환한 뒤 서버가 실행하며, 잘못된 인자는 공통 그래프에서 한 번 수정 기회를 줍니다.
- Codex 전용 분류 프롬프트 `request_router.yml`과 직접 결정 JSON을 받던 우회 분기를 제거했습니다.
- 수식 계획은 `formula.yml`, AI 조언은 `recommendation.yml`을 두 환경에서 함께 사용하고 기존 결과 검증·승인 절차를 유지합니다.
- `KCS_ENV=external`은 `config.yml`의 Codex 모델과 실행 계정의 Codex CLI 로그인을 사용합니다. `codex exec --ephemeral --output-schema` 지원 버전이 필요합니다. 확인한 CLI는 0.166.0입니다.
- 이것은 **이 서버가 호출하는 Codex 연결 방식**입니다. 별도로 연 Codex 데스크톱 대화가 자동으로 이 서버를 사용하는 것은 아닙니다.

실제 모델의 요청 해석을 비교하려면 프로젝트 루트에서 다음을 실행합니다. 합성 열 정보와 요청 6개를 사용하며 Excel 파일을 읽거나 수정하지 않습니다. 모델 호출은 발생합니다.

```sh
PYTHONPATH=src KCS_ENV=external .venv/bin/python scripts/evaluate_routing.py
# 내부망에서는 같은 사례를 내부 모델로 실행
PYTHONPATH=src KCS_ENV=internal .venv/bin/python scripts/evaluate_routing.py
```

조건부 수식 추출·단순 분리·모델 후보 추출·도움 카드·AI 의견·명시한 결과 열을 각각 검사하고 실패 시 종료 코드 1을 반환합니다. 분류 통과는 실제 Excel 계산 결과나 26B의 모든 요청 정확도를 보장하지 않습니다.

## 테스트

프로젝트 루트에서 실행합니다. 설치된 프로젝트 Python 환경과 Node.js를 사용하며 외부 모델 호출은 하지 않습니다.

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/backend -p 'test_*.py'
node --test tests/frontend/*.cjs
```

- `tests/backend/`: API·워크플로우·수식 검증·AI 조언 집계, 페이지 자산 경로와 버전 검사.
- `tests/frontend/`: 수식 대량 작성·실패 처리, 작업 전환, AI 조언 집계, 채팅 중지·실제 결과 미리보기·적용 연결. 통합 조사에서는 기존 열 반복 반영, 조건 열 자체 수정, 떨어진 행 쓰기, 정렬·열 이동, 원본 열 추가와 값 형식 보존, 수식 차단, 화면 설정·복원을 검사합니다.
- `tests/helpers/`: Excel API와 화면 DOM의 테스트 대역. 실제 Excel 렌더링·계산 엔진을 대신하지 않습니다.

배포 전 실제 Excel에서 작업표 생성 → 대표값 적용 → 치환 → 이전 결과 대상으로 전환 → 수식 적용을
확인합니다. 채팅의 정제·추출·유사도 전환, 새 열/기존 열 변경과 요청 중지도 확인합니다. 테스트·신규 모듈이 누락되지 않게
Git의 새 파일 목록을 확인합니다. API 소스에는 테스트용 실행 코드를 넣지 않습니다.

화면 HTML은 저장하지 않도록 전달하고, 연결된 JS/CSS에는 파일 내용에 따른 버전을 붙입니다. 기존 화면이 계속 보이면 `src/manifest.xml`을 Excel에 다시 등록해 새 진입 주소 `taskpane-current.html`을 사용하세요. 등록 파일 버전은 1.0.1.0입니다. API 재시작만으로 이미 열린 화면은 갱신되지 않습니다.

작업 결과 열을 삭제하면 다음 요청이나 작업 화면을 열 때 열 목록·작업 대상·마지막 결과를 함께 갱신합니다. 삭제된 대상은 남아 있는 결과 열 또는 업무 기본 열로 돌아가며, 이전 개별 작업표의 필수 세 열 삭제는 계속 차단합니다. 통합 조사에서는 역할이 필요한 기능을 실행할 때 해당 역할을 확인합니다. 조건 열을 삭제하면 자동으로 전체 행을 처리하지 않고 조건을 다시 지정하게 합니다. 입력 검증으로 거절된 채팅 요청은 오래된 요청 문맥을 버리고 다시 보낼 수 있습니다.
