# KCS_HARNESS

Excel Add-in에서 모델규격·해외거래처 데이터를 작업 시트로 가져와 전처리하고, 사람이 결과를 검토하는 PoC입니다.

## 사용 흐름

1. 홈에서 **통합 조사 시작**을 선택하고 머리글을 포함한 원본 범위를 등록합니다. 처음 선택하지 않은 같은 원본 시트의 열도 나중에 추가할 수 있습니다.
2. 지금 가져올 열을 최소 하나 선택합니다. 공급자명·부호·국가·품명·모델규격 역할은 선택 사항이며 나중에 지정할 수 있습니다. 특정 이름의 판정 열을 요구하지 않습니다.
3. **작업 시작**을 누르면 등록 범위 전체의 계산된 값과 표시 형식을 숨김·보호 보관 시트에 복사하고, 선택한 열만 조사 작업표로 가져옵니다. 원본은 수정하지 않습니다. 보관본 때문에 통합문서 용량과 초기 복사 시간이 늘어납니다.
4. 전처리·분리·대표값 적용·치환·매핑·값 지정을 설정합니다. 결과 위치를 **새 열** 또는 **기존 열**로 선택하고 미리보기를 확인한 후 반영합니다. 기존 열은 대상 행의 값만 바뀌며, 다른 행의 기존 값은 유지됩니다. 수식 셀은 덮어쓰지 않습니다.
5. 사람이 작업표 안에 만든 열도 **열 목록 새로고침**으로 사용할 수 있습니다. 열 이름·위치 변경과 표 전체 정렬 후에도 ID로 연결하며, 직접 고친 값은 다음 연산에서 다시 읽습니다. 삭제 후 같은 이름으로 만든 열은 별개입니다.
6. **후속 작업 대상**에서 임의의 열과 조건을 저장하면 정제·유사도·추출 추천·AI 의견이 일치 행만 사용합니다. 같음/다름/포함은 표시 문자열의 대소문자·공백을 구분하며, 빈칸 조건은 공백만 있는 셀도 포함합니다. 현재는 한 열의 한 조건을 지원합니다.
7. **열 추가**는 같은 원본 시트의 머리글을 조회합니다. 처음 보관한 열은 당시 값을, 처음 선택하지 않은 열은 현재 원본 값을 읽어 작업표 전체 행에 추가합니다. 작업표의 원본 행 번호로 맞추므로 작업표를 정렬해도 대응하며 숫자·논리값·표시 형식도 유지합니다. 기존 열을 덮어쓰지 않습니다.
8. **현재 대상 열의 최종 결과 확인**으로 행 수·빈 셀 수를 확인하고 결과를 채택합니다. 확정한 열도 다시 수정·확정할 수 있으며 잠금이나 과거 값 복원 기능은 아닙니다.

기존 개별 작업표도 이어서 사용할 수 있지만 자동 병합하지 않습니다. 원본 보관본이 없는 이전 작업표는 원본 열 추가를 지원하지 않습니다. 내부 **원본 행 번호**는 수정·삭제하지 않습니다. 행 ID가 없거나 중복된 행을 발견하면 처리를 중단합니다. 열 이동은 표 열 전체를 이동하고 정렬은 표 전체에 적용합니다. 셀 값만 복사해 다른 열을 덮어쓰는 동작은 열 이동으로 판별하지 않습니다.

상단 버튼은 작업표가 없으면 **작업 준비**, 준비된 작업표가 있으면 **열 추가**로 표시됩니다. **열 추가**를 누르면 원본 열을 체크박스로 여러 개 선택해 한 번에 가져오는 화면이 열리며, 전처리 완료로 작업 카드가 닫혀도 사용할 수 있습니다. 열 추가 화면에서는 **후속 작업 대상**과 **AI 의견 주제** 설정을 숨기고, 가져오기와 전처리를 이어서 할 수 있습니다. 저장된 행 조건은 유지하며 처리 영역에 현재 조건을 표시합니다. 여러 열 중 일부만 성공하면 성공한 열의 연결 정보를 먼저 저장하고 나머지는 중단합니다. **정제 도움**은 작업 카드 안에 있습니다. 원본 시트에 더 가져올 열이 없으면 안내를 표시하고 가져오기 버튼을 비활성화합니다.

처음 선택하지 않은 열을 가져올 때는 **원본 행을 정렬·추가·삭제하지 않았다는 확인**이 필요합니다. 기존 보관값과 현재 원본을 행별로 대조하고, 차이가 있으면 쓰기 전에 중단합니다. 원본 자체에는 고유 행 ID가 없으므로 보관값이 똑같은 중복 행끼리의 재정렬은 검출할 수 없습니다. 원본 순서가 바뀌었다면 이 확인란을 선택하지 않습니다. 이 제한은 원본 시트에 해당하며 작업표의 정렬·정제는 가능합니다. 같은 머리글 행을 사용하는 원본의 사용 열 최대 200개를 조회합니다.

자연어 요청은 같은 설정 카드를 채우며 자동 실행하지 않습니다. 작업표에서 수식을 요청하면 서버가 지정한 실제 입력 열로 수식 계획·승인 흐름을 엽니다. 입력 열이 모호하면 다시 확인하며 마지막 결과 열로 임의 대체하지 않습니다. 수식 화면의 원본 변경으로 직접 범위를 다시 선택할 수도 있습니다. 작업 시트 위치·열 역할·마지막 결과는 통합문서 설정에 기록되며 **저장된 작업 이어가기**로 불러옵니다.

작업을 마치거나 변경할 값이 없으면 카드는 닫히고 결과 메시지만 남습니다. 상단 **열 추가**로 작업 카드를 다시 열어 후속 작업을 할 수 있으며 진행 전인 카드는 직접 닫을 수도 있습니다. 정제규칙에는 이름만 표시하고 데이터 예시는 표시하지 않습니다. 미리보기에서는 변경 행 수와 결과 열 위치를 확인합니다. 자연어 요청에도 현재 대상의 앞 10행을 전달하며 긴 값은 1,000자까지와 잘림 여부를 함께 전달합니다.

## 처리 기준

- 전처리: 전각 ASCII/공백 변환, 앞뒤 공백 제거, 연속 공백 정리, 대·소문자 통일, 단어·기호 제거. 화면에 표시된 순서대로 실행합니다.
- 단어 제거는 대소문자를 구분하고 온전한 단어·구절을 제거합니다. 기호는 포함된 위치에서 제거합니다. 공백 정리가 필요하면 뒤에 공백 규칙을 둡니다.
- 공백 분리는 연속 공백을 합치고, 직접 지정한 구분자는 그대로 사용합니다. 모든 단어 분리 또는 마지막 단어만 추출을 선택할 수 있습니다. 마지막 단어는 두 단어 이상일 때만 추출하며 그 외에는 빈칸입니다.
- 문자열 치환은 대소문자를 구분해 찾을 문자열을 모두 바꿉니다. 정규식 없이 문자 그대로 찾으며 바꿀 문자열을 비우면 삭제합니다.
- 자동 매핑은 현재 데이터의 값 목록에서 그룹과 대표값을 지정합니다. 앞뒤 공백을 없애고 연속 공백을 하나로 합친 뒤 대문자로 비교하여 같은 그룹의 모든 행을 대표값으로 바꿉니다. 내부 공백을 전부 없애거나 비슷한 값을 추측해 묶지는 않습니다. 지정하지 않은 값과 빈 값은 유지하며 원본 값 기준으로 동시에 적용합니다.
- 같은 기준의 행에 대표값 적용: 판단 기준 열(복수 가능), 값을 바꿀 열, 대표값을 적어 둔 Excel 행 번호를 지정합니다. 공백·대소문자 정리 후 기준값이 같은 모든 행에 해당 행의 현재 셀 값 또는 직접 입력한 대표값을 적용합니다. 현재 작업 조건에 맞는 행 안에서 처리하며 기준 행도 대상에 포함되어야 합니다. 빈 기준값은 허용하지 않습니다. 기존의 묶음 번호·건수 출력은 제거했습니다.
- 값 지정: 대상 행에 입력한 문자열을 그대로 기록합니다. 빈 문자열로 비울 수도 있습니다.
- 그룹화·모델 추출의 기존 열 반영은 첫 결과값만 기록합니다. 상태는 미리보기에서 확인하고, 새 열을 선택하면 상태 열도 만듭니다. 여러 열 분리 결과는 새 열로만 저장합니다.
- Excel 화면에서 숨긴 행도 포함합니다. 애드인에 저장한 작업 조건으로 처리 대상을 제한하며, 새 결과 열의 대상 밖은 빈칸이고 기존 결과 열의 대상 밖은 유지합니다.
- 조건이 설정된 작업표의 수식 채우기는 현재 차단합니다. 조건을 해제하고 전체 범위를 명시적으로 선택한 경우에만 기존 수식 기능을 사용합니다.
- 원본 행 ID와 표·열 ID로 대상을 확인합니다. 미리보기 후 값·행 순서·표 구성이 바뀌면 다시 확인합니다. 부분 출력은 자동 재시도하지 않습니다.

## 구조와 수정 위치

아래 경로는 `src/` 기준입니다. 파일 길이보다 기능과 상태의 소유권을 기준으로 나눕니다.
기존 전역 팩토리와 `defer` 스크립트 방식을 유지하며 별도 프론트 빌드 도구는 필요하지 않습니다.

### 프론트

| 위치 | 담당 기능 |
| --- | --- |
| `static/excel/taskpane.html`, `taskpane.css` | 화면 마크업·전체 배치, 스크립트 로딩 순서 |
| `static/excel/taskpane.js` | Office 준비 상태, 컨트롤러 생성과 연결, 서버 UI 요청 전달 |
| `static/excel/chat/chat.js` | 대화 표시·저장·복원, 요청 ID, 전송·중지, 전체 작업 중 상태 |
| `static/excel/cleaning_help/` | 도움 카드 열기·닫기, 기능 선택, 작업 카드 위치 복원 |
| `static/excel/workspace/` | 작업표 생성·복원, 현재 작업표·대상·마지막 결과 관리 |
| `static/excel/workspace/source_columns.js` | 원본 보관본에서 행 ID에 맞춰 누락 열 추가 |
| `static/excel/workspace/table_reader.js` | 표·열·행 ID 확인, 공용 Excel 분할 읽기 |
| `static/excel/operations/` | 정제 설정, 미리보기·적용, 값 매핑, 일반 정제 job 통신 |
| `static/excel/operations/extraction_suggestions.js` | 전체 대상의 추출 패턴 검사와 추천 집계 |
| `static/excel/formula/` | 수식 카드, 입력 확인, Excel 수식 적용 |

| `static/excel/similarity/` | 유사도 설정·검사·결과 시트 작성 |
| `static/excel/recommendation/` | 조언 대상 검증, 전체 표 집계와 상위 조합 데이터 준비 |

작업표와 대상 상태는 `workspace/workspace.js`가 관리합니다. 수식·조언 모듈은 호출 시 현재 상태를
받아 사용하며 별도 작업표 상태를 저장하지 않습니다. 수식 결과를 마지막 결과로 등록하는 작업도
서버 완료 확인 뒤 작업표 컨트롤러에서 수행합니다. 채팅 요청·중지 상태는 채팅 컨트롤러가 관리하고
수식 컨트롤러에서도 같은 요청 수명주기 함수를 사용합니다.

스크립트 이동·추가 시 `taskpane.html`과 테스트의 로딩 경로를 함께 갱신합니다.
공용 표 읽기는 정제·조언 모듈보다 먼저, 각 컨트롤러는 마지막 `taskpane.js`보다 먼저 로드합니다.
`api/taskpane.py`가 중첩 폴더의 JS·CSS에도 내용 해시 버전을 붙입니다. 진입 URL과 API 경로는 유지합니다.

### 백엔드

- `api/`: HTTP 입력·응답과 라우트 등록. `operation_jobs.py`는 일반 정제 작업, `formula_jobs.py`는 수식 작업을 담당합니다.
- `agents/`: 자연어 요청 분류와 도구 입력 구성. 프롬프트는 `prompts/`에 유지합니다.
- `services/chat.py`, `chat_state.py`: 대화 처리와 현재 작업 문맥.
- `services/execution_history.py`: 같은 작업공간의 정제·수식 실행 이력을 현재 열 정보와 연결합니다.
- `services/operations/`: LLM 없이 수행하는 문자열 연산, 검증, 작업 상태 관리.
- `services/formula/planner.py`: 수식 모델 호출, 계획 해석, 원본·출력 범위 검증.
- `services/formula/service.py`: 수식 작업 생성·조회, 계획 진행 상태, 승인·완료·불확실 상태 관리.
- `services/recommendation/selection.py`: 대문자 기준 조합 집계·빈도 선정.
- `services/recommendation/model_io.py`: 입력 예산·분할, 모델 호출, 구조화 응답 검증.
- `services/recommendation/analysis.py`: 상위 조합 일괄 분석·제안 전체 일괄 검증과 최종 의견 작성. 해외거래처는 전체 행을 분할 검토·통합.
- `services/recommendation/service.py`: 대화 요청과 분석 연결, 작업 문맥 검증, 오류 처리.
- `repositories/`: 대화 저장소. `runtime.py`, `models/`: 모델 연결.

### 오류 문구의 책임

- 업무·설정 오류는 서버에서 결정하고 `detail` 문자열로 응답합니다. `api/errors.py`가 입력 검증 오류를 정리하며, 프론트는 서버 문구에 일반적인 실패 문구를 덧붙이지 않습니다.
- 정제 옵션의 실행 가능 여부는 `Operation.validate_ready()`에서 검사합니다. 작업 생성 때 먼저 검사하므로 잘못된 설정으로 Excel 전체 데이터를 읽지 않습니다. 자연어 라우터용 미완성 설정은 계속 허용합니다.
- Excel에서 다시 확인해야 하는 작업표·모델규격명 열 오류의 공통 문구는 `services/error_messages.json`에만 둡니다. 서버가 HTML에 안전한 JSON으로 포함하고 `common/error_messages.js`가 읽습니다. 같은 문구를 프론트 소스에 복사하지 않습니다.
- Excel 연결·범위 변경·쓰기 실패 등 클라이언트만 판단할 수 있는 검사는 유지합니다. 일부 작성·완료 미확인 경고는 재실행에 따른 중복 쓰기를 막기 위해 유지합니다.
- 서버 응답을 받을 수 없는 연결 실패·프록시 오류·잘못된 응답은 `common/api_client.js`에서 안내합니다. 요청 중지의 `AbortError`는 변환하지 않습니다.

### PDF 참고자료

1. 입력창의 **PDF 첨부**로 텍스트 PDF를 선택합니다. 작업표가 없어도 업로드할 수 있습니다.
2. 서버에서 본문·표를 Markdown으로 추출합니다. **추출 내용 보기**에서 원본 페이지 번호로 확인합니다.
3. 사용할 작업을 선택하고 **연결**을 누릅니다. 현재 작업표가 같은 종류이면 그 작업표에 연결합니다.
   작업표가 없거나 종류가 다르면 작업 종류만 저장하고, 해당 종류의 작업표를 준비·복구할 때 연결합니다.
4. 연결된 문서는 다른 작업표로 자동 이동하지 않습니다. 변경하려면 원하는 작업표에서 다시 **연결**합니다.
5. **참고자료** 버튼으로 목록을 다시 열 수 있고 **제거**하면 서버의 추출 내용·연결을 삭제합니다.

현재 단계는 첨부·추출·연결까지만 지원합니다. 문서 내용은 모델에 전달하지 않으며,
분석대상 판별·기준 해석·정제 실행·Excel 쓰기를 자동 수행하지 않습니다.

- 서버: `api/documents.py`, `services/documents/`. 화면: `static/excel/documents/`.
- `pymupdf4llm==2.1`과 잠금 파일의 의존성을 설치합니다(`uv sync --locked`).
  내부망에는 서버 OS·Python에 맞는 PyMuPDF·ONNX Runtime 등의 배포 파일도 함께 반입해야 합니다.
  AGPL/상용 라이선스의 배포 조건은 조직에서 확인해야 합니다.
- 추출은 로컬 프로세스에서 수행하며 외부 모델·OCR 서비스에 파일을 보내지 않습니다. OCR은 사용하지 않습니다.
  텍스트 없는 페이지는 번호를 표시하고, 전 페이지에 텍스트가 없으면 사용 가능 상태로 등록하지 않습니다.
- 페이지 수 제한은 없습니다. 자원 보호 한도는 파일당 25MB, 추출 본문 8MB,
  대화당 10개·본문 합계 16MB, 파일당 추출 3분, 동시 추출 2개입니다.
- 업로드·읽기 중 기존 전송 버튼이 **중지**로 바뀝니다. 중지 시 서버 요청과 추출 프로세스를 종료합니다.
  원본은 임시 파일로만 사용하고 성공·실패·중지 시 제거합니다. 추출 본문과 연결은 대화 메모리에 보관합니다.
- shortcut: PDF는 현재 API 프로세스의 대화 수명 동안만 보관합니다. 서버 재시작 후 복구가 필요하면 영속 저장을 추가합니다.
  Excel 파일에는 PDF 본문·연결을 저장하지 않습니다. 기존 대화가 살아 있으면 같은 대화의 첨부 목록을 조회합니다.

## 실행과 제한

외부용 서버는 프로젝트 루트에서 `./start-external.sh`를 실행합니다.
실행 파일은 프로젝트 폴더로 이동한 뒤 필요한 패키지를 잠금 파일 기준으로 준비하고,
`KCS_ENV=external`로 `http://localhost:8000` 서버를 시작합니다. 종료는 `Ctrl+C`입니다.
`uv`와 `codex`가 필요하며, 모델 호출 전에 `codex login`을 완료해야 합니다.
화면 주소는 `http://localhost:8000/static/excel/taskpane-current.html`입니다.
이 실행 파일은 로컬 외부 모델 테스트용이며 인터넷 공개 서버를 만들지는 않습니다.

`src/config.yml`의 환경별 `llm` 설정과 `KCS_ENV`를 사용합니다. 사용하지 않는 `storage`, `workspace`, `agent`, `mcp` 설정은 제거했습니다. API 시작 예: `PYTHONPATH=src KCS_ENV=external uv run uvicorn main:app --workers 1`.

- 작업 시트: 데이터 최대 400,000행, 원본 선택 최대 200열, 최초 복사 최대 100열, 결과 포함 최대 200열.
- 전처리·분리·치환·매핑: 요청당 최대 10,000행. 분리 최대 100열, 미리보기 결과 최대 200만 셀. Excel 읽기·쓰기 묶음은 기존 1,000행을 유지합니다.
- 매핑 목록: 한 번에 최대 1,000개 그룹을 지정합니다. 실제 값 목록은 최대 400,000행·1,600만 자에서 집계하며 화면에서는 검색 결과 최대 100개 그룹을 표시합니다.
- 기준별 대표값 적용: 판단 기준 최대 19열과 바꿀 열 1개, 기준 행을 포함한 전체 범위를 한 번에 처리합니다. 요청의 문자열 총길이는 최대 1,600만 자입니다.
- 수식: 입력 열 최대 20개, 행 범위는 Excel 시트 한도 내에서 처리합니다. 작업표 생성 한도와는 별개입니다. 모델에는 앞 20행 표본을 전달하고, 승인 후 Excel에는 1,000행씩 작성합니다. 빈 출력 범위를 다시 확인하며 부분 실패·완료 미확인은 자동 재실행하지 않습니다.
- 모델규격 AI 조언: 작업표의 현재 조건에 맞는 행에서 신고품명·거래품명·모델규격명을 대문자로 비교·집계한 빈도 상위 100개 조합을 사용합니다. 추가 열은 각 조합의 첫 실제 행 예시입니다. 상위 조합을 한 번에 분석하고 제안 전체와 중복을 제거한 근거 행을 한 번에 검증합니다. 계획·재정렬 반복은 하지 않습니다. 제안이 없으면 검증 호출은 생략합니다. 입력이 48KB 예산을 넘으면 생략·분할 없이 오류를 안내합니다. 예산은 바이트 기준이므로 모델의 실제 토큰 한도를 보장하지 않습니다. 응답 형식 오류 시 해당 호출을 한 번 재시도할 수 있습니다.
- AI 의견 진행 상황은 기존 입력창 안내 문구에 데이터 읽기 → 분석 → 전체 제안 검증 순서로 표시합니다. 기업 의견은 조건에 맞는 행의 분할 분석과 결과 통합 단계를 표시합니다. 진행 조회는 분석 중에만 수행하며 완료·실패·중지 시 종료합니다.
- 대화·정제·수식 작업은 API 프로세스 메모리에만 보관하며 서버 재시작 시 사라집니다. 통합문서의 값과 작업 정보는 유지됩니다.
- PoC 서버는 **단일 프로세스(`--workers 1`)**로 실행합니다. 여러 프로세스·서버 사이에는 메모리 상태가 공유되지 않습니다. DB 설치나 접속 설정은 필요하지 않습니다.
- 실제 처리 속도는 Excel 환경과 셀 크기에 따라 달라집니다. OfficeApi 1.9 지원 환경에서 실제 통합문서 확인이 필요합니다.

## 내부 모델과 Codex의 공통 하네스

요청 분류는 모델 종류와 관계없이 다음 경로를 사용합니다.

`채팅 → request_tools.yml → 요청 그래프 → 도구 인자 검증 → 작업 카드 → 사용자 확인 → 기존 실행 처리`

- Codex도 같은 도구 목록·실제 열 ID·최근 실행 기록을 받습니다. CLI의 구조화된 응답을 도구 호출로 변환한 뒤 서버가 실행하며, 잘못된 인자는 공통 그래프에서 한 번 수정 기회를 줍니다.
- Codex 전용 분류 프롬프트 `request_router.yml`과 직접 결정 JSON을 받던 우회 분기를 제거했습니다.
- 수식 계획은 `formula.yml`, AI 조언은 `recommendation.yml`을 두 환경에서 함께 사용하고 기존 결과 검증·승인 절차를 유지합니다.
- `KCS_ENV=external`은 `config.yml`의 Codex 모델과 실행 계정의 Codex CLI 로그인을 사용합니다. `codex exec --ephemeral --output-schema` 지원 버전이 필요합니다. 확인한 CLI는 0.166.0입니다.
- 이것은 **이 서버가 호출하는 Codex 연결 방식**입니다. 별도로 연 Codex 데스크톱 대화가 자동으로 이 서버를 사용하는 것은 아닙니다.

실제 모델의 요청 해석을 비교하려면 프로젝트 루트에서 다음을 실행합니다. 합성 열 정보와 요청 6개를 사용하며 Excel 파일을 읽거나 수정하지 않습니다. 모델 호출은 발생합니다.

```sh
PYTHONPATH=src KCS_ENV=external .venv/bin/python scripts/evaluate_routing.py
# 내부망에서는 같은 사례를 내부 모델로 실행
PYTHONPATH=src KCS_ENV=internal .venv/bin/python scripts/evaluate_routing.py
```

조건부 수식 추출·단순 분리·모델 후보 추출·도움 카드·AI 의견·명시한 결과 열을 각각 검사하고 실패 시 종료 코드 1을 반환합니다. 분류 통과는 실제 Excel 계산 결과나 26B의 모든 요청 정확도를 보장하지 않습니다.

## 테스트

프로젝트 루트에서 실행합니다. 설치된 프로젝트 Python 환경과 Node.js를 사용하며 외부 모델 호출은 하지 않습니다.

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests/backend -p 'test_*.py'
node --test tests/frontend/*.cjs
```

- `tests/backend/`: API·워크플로우·수식 검증·AI 조언 집계, 페이지 자산 경로와 버전 검사.
- `tests/frontend/`: 수식 대량 작성·실패 처리, 작업 전환, AI 조언 집계, 채팅 중지·도움 카드 연결. 통합 조사에서는 기존 열 반복 반영, 조건 열 자체 수정, 떨어진 행 쓰기, 정렬·열 이동, 원본 열 추가와 값 형식 보존, 수식 차단, 화면 설정·복원을 검사합니다.
- `tests/helpers/`: Excel API와 화면 DOM의 테스트 대역. 실제 Excel 렌더링·계산 엔진을 대신하지 않습니다.

배포 전 실제 Excel에서 작업표 생성 → 대표값 적용 → 치환 → 이전 결과 대상으로 전환 → 수식 적용을
확인합니다. 정제 도움 카드의 세 기능 전환과 요청 중지도 확인합니다. 테스트·신규 모듈이 누락되지 않게
Git의 새 파일 목록을 확인합니다. API 소스에는 테스트용 실행 코드를 넣지 않습니다.

화면 HTML은 저장하지 않도록 전달하고, 연결된 JS/CSS에는 파일 내용에 따른 버전을 붙입니다. 기존 화면이 계속 보이면 `src/manifest.xml`을 Excel에 다시 등록해 새 진입 주소 `taskpane-current.html`을 사용하세요. 등록 파일 버전은 1.0.1.0입니다. 실행 환경 확인에서 로드된 화면 버전을 확인할 수 있습니다. API 재시작만으로 이미 열린 화면은 갱신되지 않습니다.

작업 결과 열을 삭제하면 다음 요청이나 작업 화면을 열 때 열 목록·작업 대상·마지막 결과를 함께 갱신합니다. 삭제된 대상은 남아 있는 결과 열 또는 업무 기본 열로 돌아가며, 이전 개별 작업표의 필수 세 열 삭제는 계속 차단합니다. 통합 조사에서는 역할이 필요한 기능을 실행할 때 해당 역할을 확인합니다. 조건 열을 삭제하면 자동으로 전체 행을 처리하지 않고 조건을 다시 지정하게 합니다. 입력 검증으로 거절된 채팅 요청은 오래된 요청 문맥을 버리고 다시 보낼 수 있습니다.
