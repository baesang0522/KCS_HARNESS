# 현재 사용 안내

기준: 2026-11-20 코드. 과거 화면 설명은 [이전 기능 설명](history.md)에 보관한다.

## 작업표와 채팅

1. 작업표가 없으면 상단 **작업 준비**에서 머리글이 있는 원본과 가져올 열을 선택한다. 열 역할은 필요한 기능에 맞춰 지정한다.
2. **작업 시작**은 원본 값을 보관하고 별도의 작업표를 만든다. 기존 작업표는 **저장된 작업 이어가기**로 복원한다.
3. 전처리·치환·분리·대표값·유사도·수식·열 역할·작업 범위는 채팅으로 요청한다. 별도 정제 설정 카드나 작업 범위 버튼을 찾을 필요가 없다.
4. 일반 정제는 채팅에서 실제 전후 값·대상 건수·저장 위치를 확인하고 **적용/취소**한다. 새 열과 기존 열을 지정할 수 있으며 위치를 바꾸면 이전 확인은 무효가 된다.
5. 작업표가 있으면 상단 버튼은 **열 추가**다. 원본 열을 여러 개 선택하며, 일부 가져오기만 성공하면 성공한 열의 정보를 저장하고 나머지는 중단한다.
6. `새 조사 시작`, `최종 결과 기록`, `쓰기 결과 확인`은 채팅 명령으로 연결된다.

직접 수정한 셀은 다음 작업에서 다시 읽는다. 작업표 정렬·열 이동은 행·열 ID로 추적하며 내부 원본 행 번호는 수정·삭제하지 않는다. 원본에서 처음 가져오지 않은 열을 추가할 때는 원본 행 순서 확인과 보관값 대조가 필요하다. 보관값이 동일한 중복 행끼리의 원본 재정렬은 구분하지 못한다.

## 작업 범위와 결과

`판정이 Y인 행만`, `현재 대상에 회사명이 B인 행도 추가`, `그중 국가가 중국인 행 제외`, `전체 행으로 돌아가`처럼 요청한다. 범위 변경은 셀 값을 바꾸지 않는다. 조건은 최신 값으로 다시 평가하며 삭제된 조건 열을 자동으로 전체 범위로 바꾸지 않는다.

입력·범위가 바뀌면 연관 결과를 재검토 대상으로 표시한다. 결과를 자동 삭제하거나 재계산하지 않는다. 최종 결과 기록은 현재 결과의 확인 기록이며 셀 잠금·과거 값 복원 기능이 아니다.

## PDF와 거래처 비교

PDF 첨부 버튼 또는 드롭으로 여러 문서를 순서대로 처리한다. 본문·표를 읽고 조사 조건을 추출해 Excel 검토 시트에 표시한다. 모델 응답·근거 검증이 모두 성공한 경우에만 추출 조건을 저장한다.

검토 시트 수정 후 추출내용 패널의 **수정 내용 반영** 또는 같은 채팅 명령으로 확인을 준비하고 적용한다. PDF별 전처리·추출 재시도도 채팅으로 요청한다. 추출내용 패널은 닫기·Esc로 닫는다.

거래처 매칭은 반영된 PDF 기준 목록과 작업표의 고유 거래처를 비교한다. 기본은 Levenshtein, 90점 미만은 SequenceMatcher로 보완하고, 최고 점수 90 이상에 그룹을 부여한다. 특정 방식을 지정할 수도 있다. 기존 그룹·점수 열을 재사용하면 그룹이 빈 행을 처리한다. 정확한 비교·동점 규칙은 `services/supplier_matching.py`가 담당한다.

## 에이전트·수식·AI 의견

목표형 요청은 실제 Excel 조회 결과를 받아 다음 도구를 선택한다. 일반 변경은 기존 미리보기·적용 절차를 따른다. 현재 요청에서 100점 대표 부호의 같은 부호 그룹 연결을 명시한 경우에만 별도 자동 적용 경로가 활성화되며, 조회한 대표값 검증과 쓰기 보호를 거친다. 실행 실패·중복 조회·완료 미확인 상태에서는 중단하거나 사용자 확인을 기다린다.

수식은 실제 계산 결과 대신 적용 전 **계산 계획**을 보여준다. 빈 출력 범위와 입력 겹침 여부를 검사하고 승인 후 Excel에서 계산한 뒤 값으로 고정한다. 작업표의 요청한 입력 열을 전체 데이터 행에서 읽으며, 필터로 제외되거나 숨겨진 행도 계산한다. 기존 필터는 유지한다. 입력 범위를 직접 다시 선택하면 해당 범위의 모든 행을 계산한다. 복수 결과 열의 개별 재배치는 현재 제약을 유지한다. 새 수식 열은 이름만 지정하면 작업표 오른쪽 빈 공간에 준비한다. 정제의 열 삽입 위치와 달리 수식의 중간 삽입은 지원하지 않는다.

수식 계획 생성 후에도 Excel의 저장 위치·빈 출력 검증이 끝나야 적용 미리보기가 나타난다. 이 단계에서 실패하거나 미리보기를 취소하면 서버에도 `FAILED`와 이유를 기록한다. 실패한 계획은 적용할 수 없으며 원래 계산 내용·입력 열·참조 시트·결과 이름을 포함해 다시 요청한다. 실패 보고 통신도 끊기면 화면에 그 사실을 알리고, 서버에는 마지막 수신 상태가 남을 수 있다.

명시적인 AI 의견은 기업 또는 모델규격 분석으로 연결된다. 모델규격은 상위 100개 조합, 기업은 대상 행 분할 분석·통합을 사용한다. 의견 자체는 셀 변경이 아니다.

## 저장·복구와 제약

- 서버 메모리: 대화, PDF, 조사 조건, 정제·수식·에이전트 실행 기록. 재시작 후 복구되는 영구 저장소는 없다.
- 통합문서: 작업표 값·행/열 연결·작업 정보·결과 의존 관계·PDF 검토 시트. 통합문서도 저장해야 한다.
- 브라우저 저장소: 대화 ID·미완료 요청. 실제 데이터베이스가 아니다.
- 쓰기 완료 미확인은 자동 재적용하지 않는다. **쓰기 결과 확인**에서 기록과 현재 셀을 확인한다.
- 묶음 검토 UI·도구는 보류 중이다. 코드·테스트·기존 저장 정보는 보존하지만 현재 기능으로 노출하지 않는다.
- 작업표 최대 400,000행·200열, 미리보기 최대 200만 셀, 수식 입력 최대 20열 등 기존 검증을 유지한다. 상세 한도는 입력 스키마와 Excel 처리 코드가 기준이다.
- 실제 Excel 지원·렌더링·계산 엔진·대량 성능은 자동 테스트 대역만으로 보장되지 않는다.

문제 재현 시 채팅 요청부터 실제 반영·완료 미확인 상태를 연결하는 방법은 [로그 안내](logging.md)를 참고한다. 코드 이동 후에는 서버를 재시작하고 Excel 작업창을 새로 불러와 새 스크립트를 사용한다.


## PDF 조건으로 여러 번 좁히기

“이 중에서 …만 남겨”는 현재 후보와 새 조건의 교집합으로 처리한다. 숫자 범위와 AND/OR 조건을 사용할 수 있으며, 숫자를 해석할 수 없는 행은 보류로 남긴다. PDF 조건 ID·비교 규칙과 선별 단계별 결과를 기록하고, 입력이나 조건이 바뀌면 관련 단계를 재검토 대상으로 표시한다. “보류 행 다시 보기”, “해당 단계 입력 후보로 돌아가기”를 채팅으로 요청할 수 있다. 사용 예시와 제약은 [단계별 선별 안내](condition-workflow.md)를 참고한다.


### 다른 시트를 참조하는 수식

“거래처검토 시트의 회사명 목록과 해외공급자 상호를 비교해서 같으면 Y, 아니면 N을 새 분석대상여부 열에 수식으로 채워줘”처럼 요청할 수 있다. 현재 작업표의 입력 열과, 참조할 시트 이름을 따로 전달한다. 다른 시트의 열 ID를 사용자가 알아낼 필요는 없다. 시트 이름이 정확히 일치하면 그 시트를 사용하고, 이름의 시작 부분만 지정했다면 후보가 하나일 때만 연결한다. 여러 후보가 있으면 실제 시트 이름을 확인한다.

요청한 참조 시트의 실제 이름·사용 영역·표 머리글·데이터 주소와 제한된 표본을 수식 계획에 전달한다. 미리보기에서 참조 주소와 생성된 수식을 확인한다. 계획 후 참조 시트의 이름·범위·표 머리글이 바뀌면 적용 전에 다시 계획해야 한다. 참조 셀 값은 적용 시점의 값으로 계산한다. 기존처럼 계산 후 결과값으로 고정하므로, 나중에 참조 목록이 바뀌어도 이미 작성된 결과가 자동 갱신되지는 않는다.

이 기능은 일반 수식의 다른 시트 참조 지원이며, 기업 Y/N 분류 전용 작업은 추가하지 않았다. 기업 필터 후에도 전체 행에 품목 판별 수식을 계산할 수 있다. 이후 “현재 후보 중 품목 판별이 Y인 행만 남겨줘”로 요청하면 기업 후보와 품목 조건의 교집합을 선별한다.


### 거래처 유사도 결과로 기존 작업대상 변경

“해외공급자상호 정제와 거래처검토 회사명을 유사도 비교해서 90 이상이면 기존 작업대상 열을 Y로 바꿔줘”는 기존 기능 두 단계를 이어 실행한다. PDF 검토 내용을 반영한 회사 목록을 기준으로 `match_suppliers`의 새 그룹·점수 결과를 준비하고, 적용 완료 후 이번 그룹명이 있는 행만 `update_matching_rows(not_blank)`로 Y로 바꾼다. 각 단계는 기존 미리보기·적용 절차를 따르며 현재 필터와 미달 행의 기존 값은 유지한다.

기본 `auto`는 Levenshtein 최고 점수가 90 이상이면 그대로 채택하고, 90 미만인 이름만 SequenceMatcher 양방향 평균으로 다시 비교한다. 기존 작업대상 열의 N 여부와는 무관하다. 그룹명은 반올림 전 점수 90 이상일 때만 채워지므로 후속 변경은 그룹명의 유무를 사용한다. 새 비교 결과를 사용하므로 기존 그룹의 빈칸만 채우는 동작을 전체 재판별로 오인하지 않는다.

이 연결은 확인·저장된 PDF 거래처 기준을 사용한다. 서버에 반영되지 않은 일반 시트 목록의 유사도 비교 기능을 추가한 것은 아니다. 기준 목록을 수정했다면 먼저 기존 PDF 검토 내용 반영을 수행한다.


### 명시한 열에서 모델 추출

“품목검토 시트의 규격을 모델규격명에서 찾아 새 모델 열과 옆 분류 열에 적어줘”처럼 입력 열을 명시하면, 그 열의 기존 역할과 관계없이 기존 PDF 기준 추출 미리보기를 준비한다. 입력 열 역할을 바꾸지 않는다. 입력 열을 생략한 경우에만 유일한 `model_spec` 역할 열을 사용하며, 없거나 여러 개면 대상 열을 확인한다.

기준은 확인·반영된 PDF 품목 목록이다. 실제 값은 기존 미리보기의 적용 후 모델명과 PDF 분류 두 열로 저장하며, 미검출·복수 모델 처리와 현재 행 필터는 기존 동작을 유지한다. 치수 파싱의 역할 검사는 이번 변경 대상이 아니다.


### 수식 계획 실패와 재생성

정확 일치 Y/N 등 수식 요청은 기존 Excel 수식 경로를 사용한다. AI 응답의 JSON 형식·계획·입출력 범위·참조 시트 검증이 실패하면 같은 요청 안에서 오류를 전달해 한 번 재생성한다. 입력 열·참조 시트·전체 행 범위는 유지하며, 재생성까지 기존 계획 시간 한도를 적용한다. 통신 오류·시간 초과·사용자 중지는 자동으로 재시도하지 않는다.

검증을 통과한 계획만 Excel 출력 위치 확인을 거쳐 적용 미리보기로 연결한다. 재생성도 실패하면 이전 미리보기를 남기지 않는다. 미리보기 이후 적용 직전 입력·출력 검증에서 실패하면 미리보기를 닫고 서버에도 실패를 기록한다. 이미 적용 승인을 요청한 뒤의 통신 실패는 기존 완료 미확인 처리로 남기며 다시 쓰지 않는다.
