# PDF 조건으로 단계별 행 선별

보고서 생성은 포함하지 않는다. 원본은 보존하고 조사 작업표에서 전처리·선별한다. PDF 조건 검토의 `confirmed`와 실제 행 선별의 `applied`는 서로 다른 상태다. `applied`는 해당 단계의 비교 규칙 적용이며, PDF 전체 요건 충족이나 기업 동일성 확정을 뜻하지 않는다.

## 대화 예시

1. PDF를 첨부하고 기업·품목·원문 근거를 검토한 뒤 수정 내용을 반영한다.
2. “기업 A와 B에 해당하는 거래만 남겨.” 기업명 정제·비교 결과를 확인하고 기업 조건을 적용한다.
3. “이 중에서 HS가 지정 코드이고 두께가 0.5~1.0mm인 것만 남겨.” 필요하면 기존 규격 파서로 두께를 먼저 추출한다. 열·단위·기업별 품목 관계가 불명확하면 채팅으로 확인한다.
4. 범위 변경 결과에 이전/이후 행 수와 판단 보류 수가 표시된다. “그 단계의 보류 행 다시 보자”로 보류 범위를 열고 전처리 또는 사용자 판단을 반영한다.
5. 보류 행 수정 후 기존 통과 행까지 함께 재선별하려면 “그 품목 단계의 입력 후보 전체로 돌아가서 다시 적용해”라고 요청한다. 보류 범위만 열면 현재 대상도 보류 행뿐이며 기존 통과 행을 자동 합치지 않는다.
6. “어떤 조건을 적용했고 무엇이 남았어?”라고 물으면 단계별 규칙·조건 연결·건수·재검토 사유를 확인할 수 있다. 최신 값은 실제 조회로 확인한다.

기업과 품목 순서는 고정하지 않는다. 특정 판정 열을 요구하지 않으며 기존 전처리의 미리보기·적용과 원본 보호는 유지한다.

## 범위와 비교 규칙

- `intersect`: 현재 후보 중 새 조건을 만족하는 행만 남긴다. 호출 당시 후보의 행 식별값을 경계로 저장하므로 이후 값 수정으로 이전 후보 밖의 행이 들어오지 않는다.
- `replace`: 기존 조건을 새 조건으로 교체한다.
- `include` / `exclude`: 기존처럼 전체 작업표에서 조건 일치 행을 추가 / 현재 후보에서 제외한다.
- `clear`: 전체 작업표로 돌아간다.
- `revisit_selection`: 기록된 단계의 보류 행(`pending`) 또는 입력 후보(`input`)로 돌아간다. 정렬 뒤에도 행 식별값을 사용하며 삭제된 행이 있으면 중단한다. 과거 셀 값은 복원하지 않는다.

문자열 일치·불일치·포함·빈칸 조건에 `gt/gte/lt/lte` 숫자 비교가 추가된다. 비교 전 단위를 정리해야 한다. 단위가 붙은 값, 천 단위 쉼표, 빈칸, NaN, 무한대 등은 숫자로 추정하지 않는다. 유효 숫자의 소수 비교는 문자열을 수치로 해석해 정밀도 손실 없이 수행한다. HS 코드는 문자열 비교로 앞자리 0을 보존한다.

복합 조건의 `all`은 AND, `any`는 OR다. `(기업 A AND 품목 X) OR (기업 B AND 품목 Y)` 관계를 그대로 표현한다. 모르는 관계를 코드가 추론하지 않는다. 숫자 해석 불가의 평가값은 `null`이다. AND에서 하나라도 명백한 불일치이면 제외, OR에서 하나라도 일치하면 포함하며, 나머지 불확실한 경우는 보류다. 보류 행은 현재 통과 범위에서 빠지지만 제외 확정과 구분해 기록한다.

## 조건 연결·단계 기록

`change_scope`의 `condition_ids`와 `note`가 확인된 PDF 조건과 실제 열·비교 규칙을 연결한다. 서버가 해당 조건의 내용 해시(`condition_versions`)를 부여하고 Excel 범위 적용 직전에 최신 버전을 다시 확인한다. 검토 시트에서 값이 그대로인 조건은 순서를 바꿔 저장해도 ID를 유지한다. 수정된 조건은 새 ID를 받아 이전 연결이 무효화된다. 중복 조건도 각각의 ID를 유지한다.

`workspace.selection_stages`에 단계 ID, 상위 단계, 원래 채팅 요청 ID, 적용 규칙, PDF 조건 버전, 입력·포함·제외·보류 행 식별값과 입력 검증 정보를 저장한다. 셀 원문 전체를 단계에 복제하지 않는다. 이 기록은 기존 통합문서 설정 저장을 사용한다. 서버에 전달하는 단계 문맥에는 행 목록 대신 규칙·건수·상태 요약을 보낸다. 현재 범위의 행 ID는 실행 검증용으로 서버에 전달하지만, 모델 입력에서는 개수로 요약해 대량 ID가 문맥을 차지하지 않게 한다.

조건·입력값·행 구성·연결 열이 바뀌면 해당 단계와 연결된 후속 단계를 `needs_review`로 표시한다. 자동 재실행하거나 셀을 되돌리지 않는다. 일반 전처리는 계속할 수 있으나 재검토 중인 최종 선별 결과는 확정할 수 없다. 이전 후보로 돌아가 명시적으로 다시 선별하거나 새 범위를 지정한다. 범위와 단계 기록은 함께 저장하며 실패하면 메모리 상태를 되돌린다.

## PoC 범위와 검증

기업 필터가 설정되어 있어도 수식을 사용할 수 있다. 자동 입력 범위는 작업표 전체 데이터 행이며 필터로 제외되거나 숨겨진 행까지 계산한다. 직접 입력 범위를 다시 선택한 경우에는 그 범위의 모든 행을 계산한다. 기존 필터와 선별 기록은 유지하고, 빈 출력 보호·입력 변경 검사·부분 실패 복구도 그대로 적용한다.

예: 기업 조건으로 선별 → “전체 행에 품목 판별 수식을 새 열로 계산해줘” → 수식 미리보기 확인·적용 → “현재 기업 후보 중 품목 판별이 Y인 행만 남겨줘”. 마지막 단계는 `intersect`로 현재 기업 후보 안에서만 좁히므로 다른 기업이 다시 포함되지 않는다. 수식 결과는 계산 후 값으로 고정되며, 나중에 입력이 바뀌면 자동 재계산 대신 관련 결과가 재검토 대상으로 표시된다.

PDF OCR과 서버 대화 영속 저장도 기존 제약을 유지한다. 통합문서의 선별 기록이 남아 있어도 서버 재시작으로 PDF 조사 상태가 사라지면 이전 PDF 연결을 유효하다고 간주하지 않는다. PDF를 다시 확인하고 조건을 연결해야 한다.

자동 테스트는 교집합·순서 변경·정렬·빈 결과·숫자 경계·복합 조건·보류 재처리·조건 버전 변경·삭제 행·실패 시 복구와 기존 기능 회귀를 검사한다. 실제 모델의 도구 선택, 실제 Excel 호스트, 대용량 단계 기록의 저장 용량과 처리 시간은 별도 확인이 필요하다. 단계가 많으면 입력 변경 검사의 읽기 작업과 통합문서 설정 크기도 증가한다.
